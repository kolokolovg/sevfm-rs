# Rust-конвенции sevfm-rs

Пишем безопасный, производительный и идиоматичный Rust: система типов
устраняет классы багов на этапе компиляции. Единственный контракт
поведения — спецификации `openspec/specs/` (и design.md активного change
для инженерных решений). Как именно требования реализованы — свободный
выбор: структуры данных, модель исполнения и крейты определяются фазой
и фиксируются в её design.md, а не наоборот.

## Главные принципы

- Сначала корректность, потом производительность. Компилятор — союзник:
  не воюй с borrow checker — перепроектируй поток данных.
- `unsafe` — только при строгой необходимости; каждый блок — с
  `// SAFETY:` комментарием об инварианте.
- Zero-cost абстракции: если абстракция добавляет рантайм-накладные —
  пересмотреть.
- Невыразимые некорректные состояния: enum и система типов вместо
  наборов bool/Option (статус процесса — enum исходов, а не три флага).

## Ownership и заимствования

- Owned-типы по умолчанию (`String`, `Vec<T>`, `PathBuf`); параметры
  на чтение — `&str`/`&[T]`; `impl AsRef<str>` — если нужно и то и другое.
- `Cow<'_, str>` — когда функция может обойтись без аллокации.
- `Clone` — не пластырь от ошибок borrow checker: перестраивай код,
  чтобы времена жизни сходились естественно.
- `Arc<T>` — разделяемое владение между потоками; `Mutex<T>`/`RwLock<T>`
  — внутренняя мутабельность внутри.

## Времена жизни

- Elide, где компилятор выводит сам; аннотируй только по его требованию.
- Осмысленные имена в сложных сигнатурах: `'input`, `'conn` — не `'a`.
- Если структура держит ссылку — данные переживают структуру; сложные
  времена жизни — сигнал перейти к owned.
- `'static` — только действительно статические данные или требование
  трейт-баундов.

## Обработка ошибок

- `thiserror` — для библиотечного кода (`lib.rs`): derive `Debug`+`Error`,
  сообщения в `#[error("…")]`, по-русски, с контекстом. `anyhow` —
  допустим в прикладном (`main.rs`), где тип ошибки не важен.
- Конверсии через `From<SourceError>` (или `#[from]`, когда смысл
  сохраняется), распространение — оператором `?`.
- `.unwrap()` — только в тестах. `.expect("почему инвариант верен")` —
  лишь с документированным и доказуемым инвариантом.
- `Result<T, E>` для всех fallible-операций; `Option<T>` — только для
  действительно необязательных значений, не как код ошибки.

## Async-рантайм

- `tokio` — async-рантайм по умолчанию, версия зафиксирована в
  `Cargo.toml`.
- `tokio::spawn` — независимые конкурентные задачи; `tokio::join!` —
  задачи, которые должны завершиться все; `tokio::select!` — гонки
  futures, всегда с cancellation-safe веткой.
- Не блокировать рантайм: CPU-heavy и синхронный I/O — в
  `tokio::task::spawn_blocking`.
- Межзадачное общение — каналы `tokio::sync` (`mpsc`, `broadcast`,
  `watch`).
- Синхронный `std` без async — легитимный выбор; решение принимается
  на фазу по требованиям спеки (латентность, отзывчивая остановка) и
  фиксируется в design.md.

## FFI и unsafe

- FFI-вызовы — в безопасных обёртках, unsafe-граница минимальна.
- `bindgen` для генерации биндингов из C-заголовков.
- Указатели из чужого кода валидируются до разыменования.
- Каждый `unsafe`-блок — `// SAFETY:` с объяснением инварианта.
- `#[repr(C)]` для структур через FFI-границу.

## Производительность

- Бенчмарки — `criterion`, профилирование — `perf`/`flamegraph`/`samply`:
  когда есть измеримая проблема, не заранее.
- Стек вместо кучи для малых фиксированных коллекций; `SmallVec`/
  `ArrayVec` для обычно-малых.
- Горячие пути — без лишних аллокаций: буферы переиспользуются через
  `clear()`, аллокации выносятся из цикла.
- `#[inline]` — только маленькие частые функции библиотеки; в
  прикладном коде решает компилятор.
- Итераторы вместо индексных циклов — компилятор оптимизирует их лучше.

## Структура проекта

- Библиотека (`src/lib.rs`) отделена от бинарника (`src/main.rs`):
  переносимая логика — в библиотеке; `main.rs` — только CLI-обвязка
  (аргументы, сигналы, коды выхода). `tests/` импортирует библиотеку
  и не дублирует константы.
- Модули по домену, не по типу (`pipeline`, `icy`, `ui` — не
  `models`/`utils`/`helpers`).
- `pub(crate)` для внутреннего; `pub` — только публичный контракт
  текущей фазы.
- Workspace — если проект станет мульти-крейтовым; сейчас один крейт.
- Зависимости: минимум; `default-features = false` + явные features;
  каждый крейт — с комментарием-обоснованием в `Cargo.toml`; прежде чем
  добавить крейт — проверить, не решает ли `std`. Compile-time крейты
  (proc-macro: `thiserror`, будущий Slint) допустимы. `Cargo.lock`
  закоммичен.

## Тесты

- Юнит-тесты — `#[cfg(test)] mod tests` внутри модуля.
- Интеграционные — в `tests/` на публичное API; бинарные фикстуры — в
  `tests/fixtures/`.
- Для парсеров байтов (ICY-метаблоки, фаза 2) — property-based
  (`proptest`/`quickcheck`) и табличные случаи на реальных байтах:
  валидный блок, обрезанный, мусор между блоками, смена посреди блока.
- `mockall` — для моков трейтов, когда трейты появятся.
- Живые тесты (сеть, аудиоустройство) — `#[ignore]` с комментарием,
  как запускать.

## Стиль и комментарии

- Комментарии и doc-комментарии — по-русски; идентификаторы — строго
  по-английски.
- Каждый новый файл `.rs` — с лицензионной шапкой Apache-2.0 (копировать
  из `src/main.rs`).
- `///` — контракт сущности (что и зачем); `//` — только нетривиальные
  решения. Закомментированный код и «дневниковые» комментарии — удалять.
- Константы — UPPER_SNAKE, значения — из спеки; магические числа и
  строки в логике — находка.
- Сообщения для пользователя — по-русски, с префиксом `sevfm: ` (stderr).

## Чек-лист ревью

Находка — если в коде есть:

- `unwrap` вне тестов без обоснования;
- `Clone` как обход borrow checker;
- новая зависимость без обоснования в `Cargo.toml` или с лишними
  features;
- блокировка async-рантайма (синхронный I/O вне `spawn_blocking`);
- `unsafe` без `// SAFETY:`;
- magic numbers/strings вместо констант;
- `pub` без нужды (не контракт текущей фазы);
- дублирование знания между `lib` и `tests` (константа в двух местах);
- аллокации внутри горячего цикла;
- поведение за рамками требований текущей фазы openspec.

## Перед сдачей задачи

1. `cargo clippy --all-targets -- -D warnings` — чисто.
2. `cargo test` — зелёные.
3. `cargo fmt --check` — чисто (иначе `cargo fmt`).
4. Каждый `unsafe`-блок — с `// SAFETY:`.
5. При правке `Cargo.toml` — `cargo build` собирается, `Cargo.lock`
   закоммичен вместе с манифестом.

## Порядок применения

1. Прочитай окружение: как оформлено рядом — следуй местным конвенциям,
   не своим привычкам.
2. При правке: минимальный дифф; не рефакторить «заодно» то, что не
   просили.
3. При ревью: пройди чек-лист, верни список
   `путь:строка — запах — как чинить`, сортированный по важности.
4. Поведение сверяй со спекой фазы, а решения — с её design.md.
