# Proposal

## Why

Смена трека в представлении (окно, трей, MPRIS, headless-печать) происходит в момент приёма метаблока из сети, а звук отстаёт от сети на заполненность кольцевого буфера: предбуфер 64 КиБ ≈ 3 с при ~22 КиБ/с потока, до ~23 с при полном 512 КиБ. Пользователь видит заголовок следующего трека за секунды до того, как тот зазвучит. Синхронизация была сознательно отложена из add-player-ui в отдельный change — этот change закрывает долг.

Ручная проверка фазы вскрыла смежный дефект машины вывода: rodio 0.23 дёргает `Source::next` прямо в аудио-колбэке устройства, а underrun-пауза `BufferReader` блокирует его до повторного предбуфера — при обрыве сети дольше ~30 с PipeWire убивает поток, сессия фальшиво завершается Fatal «аудиоустройство» вместо требуемого спекой audio-pipeline автоматического возобновления. Фикс включён в этот change по решению пользователя.

## What Changes

- Приём метаблока больше не меняет текущий трек напрямую: метаблоки становятся в очередь с привязкой к смещению в аудиобайтах (единая шкала — аудиобайты, прошедшие через буфер сессии).
- Кольцевой буфер получает монотонный счётчик прочитанного — позицию звучащего звука в той же шкале.
- Дренаж очереди в тике сессии: смена трека публикуется, когда звучащее смещение достигает смещения метаблока (точность — период опроса). UI, трей, MPRIS и headless-печать не меняются — все уже читают тик сессии.
- Станция (`icy-name`) по-прежнему отображается сразу: она идентифицирует станцию, а не «сейчас играет».
- Во время буферизации заголовок замирает (счётчик не растёт — очередь не дренируется) — корректное поведение без специального кода.
- При мусорном переподключении (очистка буфера) ожидающие (недренированные) смены трека сбрасываются, чтобы смена из старого соединения не появлялась с опозданием; при кратком обрыве без очистки буфера ожидающая смена публикуется по звуку, как обычно.
- Тесты icy в `net_reader` переделываются: трек наблюдается после симуляции воспроизведения, а не сразу после отправки метаблока; добавляются тесты очереди (порядок, недобор смещения, буферизация, переподключение).
- Декодирование уходит с аудио-колбэка в выделенный поток: сэмпл-FIFO между ними, при голоде колбэк отдаёт тишину, не блокируясь; длинная буферизация перестаёт убивать аудиопоток (фикс по итогам ручной проверки).
- Текст ошибки cpal вывода логируется (сейчас глотается) — настоящая причина гибели аудиопотока видна в stderr.

## Capabilities

### New Capabilities

(нет — поведение принадлежит существующей границе icy-metadata)

### Modified Capabilities

- `icy-metadata`: добавляется требование синхронизации смены трека с воспроизводимым звуком — представление меняет трек, когда звучит относящееся к метаблоку аудио, а не при приёме; станция — сразу; точность ограничена периодом опроса; при буферизации заголовок не меняется; при переподключении ожидающие смены сбрасываются.

## Impact

- **Код**: `src/buffer.rs` — монотонный счётчик прочитанного; `src/net.rs` — очередь метаблоков вместо прямой записи трека в `pump`, сброс очереди при переподключении; `src/session.rs` — дренаж очереди в `tick()`; `src/pipeline.rs` — декод-поток и сэмпл-FIFO (`Mp3Source` худеет до читателя FIFO), логирование текста ошибки cpal — в `session.rs`.
- **Код без изменений**: `src/main.rs`, `src/ui.rs`, `src/tray.rs`, `src/mpris.rs`, `src/mpris_service.rs`, `src/cover.rs` — все потребители читают `SessionTick`, источник значения меняется под ними.
- **Обложки**: поиск обложки стартует в момент, когда трек зазвучал (а не раньше) — побочный плюс, код обложек не трогается.
- **Тесты**: переделка `tests/net_reader.rs` (4 icy-теста), правка ожиданий `tests/cli_mock.rs` (тайминг headless-печати), новые тесты очереди/дренажа.
- **Зависимости**: новых нет.
