# Design

## Context

Мотивация — proposal.md (Why). Текущий тракт: `pump` (`src/net.rs:672`) получает из `IcyFramer` (`src/icy.rs:55`) фреймы `Frame::Audio | Frame::Meta` (`src/icy.rs:33`); аудио идёт в `RingBuffer` (`src/buffer.rs:107`, `write` по `(head+len) % cap`), а метаблок немедленно пишется в `now_playing.track` (`src/net.rs:762–770`). Потребители (окно, трей, MPRIS, headless) читают снапшот `SessionHandle::tick()` (`src/session.rs:114`) с периодом `POLL_INTERVAL` = 100 мс. Позиции звучащего звука нигде нет: `RingBuffer` хранит `head/len` по модулю ёмкости, монотонного счётчика прочитанного нет. Ключевой факт, делающий честный синк дешёвым: фреймер уже вырезал метаблоки до буфера — кольцо содержит только аудиобайты, существует единая естественная шкала «аудиобайты сессии».

## Goals / Non-Goals

**Goals**

- Смена трека публикуется в момент, когда соответствующее аудио звучит; допуск — период опроса (спека: ≤ 0,5 с).
- Ноль изменений в потребителях (`main.rs`, `ui.rs`, `tray.rs`, `mpris*.rs`, `cover.rs`) — все уже читают тик.
- Единая шкала смещений, корректная на переподключениях и очистках буфера.

**Non-Goals**

- Сэмпл-точная синхронизация (достаточно байтовой шкалы; 100 мс ≈ 2,2 КиБ потока).
- Синхронизация названия станции — оно идентифицирует станцию, а не «сейчас играет», остаётся немедленным.
- Задержка заголовка «на оценку заполненности буфера» — костыль с рассинхроном на обрывах и дрейфом, отклонён ещё при оценке в add-player-ui.
- Перекладывание ожидающих метаблоков между эпохами (пересчёт смещений после обрыва) — сброс проще и достаточен.

## Decisions

### D1: Шкала — кумулятивные аудиобайты сессии; метаблоки — в очередь
В `reader_loop` (`src/net.rs:510`) появляется счётчик `session_audio: u64` — все аудиобайты, записанные в кольцо за жизнь сессии, без сброса на переподключениях (счётчик `audio_bytes` мусорного бюджета в `pump` живёт одно соединение, переиспользовать его нельзя). Обработка фреймов в порядке потока: `Audio` → `buffer.write` + `session_audio += len`; `Meta` → `parse_meta` → `ether_gate.push(session_audio, track)` — смещение метаблока равно «всему аудио до него», т.е. метаблок относится ко всему аудио после записи. u64 при ~22 КиБ/с не переполняется тысячелетиями.

*Альтернатива*: позиция в сэмплах из декодера (`Mp3Source`, `src/pipeline.rs:722`) — точнее, но вторая шкала и межпоточная передача декодированной позиции; байтовая шкала уже есть в точке записи. Отклонена.

### D2: `EtherGate` — очередь метаблоков в `src/icy.rs`
`EtherGate { queue: Mutex<VecDeque<(u64, TrackInfo)>> }` рядом с `NowPlaying` (`src/icy.rs:170`): `push(offset, track)`, `drain_until(pos) -> Option<TrackInfo>` (выталкивает все записи с `offset ≤ pos`, возвращает последнюю; пусто → `None`), `reset()`. ~70 строк, отдельный модуль не заводим. Создаётся в `PlayerSession::start` (`src/session.rs:162`) рядом с `now_playing`; `Arc` уходит в reader (push) и в `tick` (drain). Читатель трека больше не пишет `now_playing.track` вовсе — единственный писатель трека теперь дренаж, станцию по-прежнему пишет reader (`src/net.rs:538–543`).

### D3: Позиция звука — `total_read: AtomicU64` в `RingBuffer`
Счётчик растёт в read-пути кольца (`buffer.rs:235–290`) на число байт, реально отданных потребителю (декодеру), монотонен сквозь `clear()` (`buffer.rs:244` — clear выбрасывает непрочитанное, счётчик чтения не трогает). Наружу — `total_read() -> u64` (`load(Relaxed)`). Relaxed достаточен: дренаж читает атомик, затем берёт мьютекс очереди; гонка даёт запаздывание на один опрос (100 мс), монотонность гарантируется атомарным RMW. Байты поиска первого кадра читаются тем же read-путём — шкалы записи и чтения совпадают по построению.

После D8 счётчик перестал быть позицией звучания (декодер бежит впереди звука на полный FIFO): теперь это шкала декодера, по которой тракт штампует метки чанков; дренируют ворота по позиции потребителя `sound_pos` (D8).

*Альтернатива*: считать в `BufferReader` (`src/pipeline.rs`) — тот же путь, но счётчик в кольце покрывает любого потребителя и держит шкалу внутри одной структуры. Отклонена.

### D4: Дренаж в `SessionHandle::tick()`
Перед снапшотом `now_playing`: `pos = sound_pos.load(Relaxed)` (позиция звучания от потребителя сэмплов, D8); `if let Some(t) = ether_gate.drain_until(pos) { now_playing.lock().track = Some(t) }`. Все потребители уже опрашивают тик (UI-таймер `main.rs:611`, headless `main.rs:446`, MPRIS-снапшот) — синк доезжает до них без правок. Допуск = 100 мс опрос + буфер устройства rodio (десятки мс) ≪ 0,5 с спеки. Порядок локов единственный: `queue → now_playing`; reader берёт их порознь (`push` только queue, станция — только now_playing), цикла нет.

*Альтернатива*: дренаж в `pump` — reader спит в бэкоффе/коннекте, пока буферизованное аудио продолжает звучать; заголовок замерал бы на время переподключения. Отклонена. Выделенный поток дренажа — лишний: работа уже выполняется каждые 100 мс.

### D5: Сброс очереди — только при очистке буфера
`reset()` вызывается там же, где `buffer.clear()` (мусорное переподключение, `src/net.rs:564, 572`): аудио, на которое ссылаются ожидающие записи, выброшено — записи никогда не «прозвучат», а без сброса total_read дошёл бы до их смещений на новом соединении и показал трек, принятый до разрыва, посреди новой эпохи. Наоборот, при кратком обрыве без очистки буферизованное аудио продолжает звучать — записи валидны и обязаны дренироваться (сценарий «Краткий обрыв не теряет смену»); сбрасывать нельзя — заголовок застрял бы до следующего метаблока. `now_playing.track` (последний показанный) сброс не трогает: при обрыве текущий трек остаётся видимым (требование player-ui).

Компромисс: вместе с никогда не прозвучавшими сбрасываются и записи с `offset ≤ total_read`, чьё аудио уже прозвучало, но тик не успел их дренировать (окно ≤ 100 мс до очистки) — редчайший путь, публикация восстановится первым метаблоком нового соединения.

### D6: `SessionTick` и потребители не меняются
`tick()` дренажирует и снапшотирует как раньше; поля `SessionTick` (`src/session.rs:55`) прежние. Изменяются подписи внутренностей: `spawn_reader` принимает `Arc<EtherGate>`, `pump` — `&mut session_audio` и ссылку на гейт. Headless-печать «сейчас в эфире» автоматически становится синхронной со звуком — отдельного кода не требуется.

### D7: Тесты
- **Юнит `icy`**: `EtherGate` — порядок push/drain, недобор смещения (`None` до порога), несколько записей одним дренажём (побеждает последняя), `reset`, drain после reset.
- **Юнит `buffer`**: `total_read` растёт на прочитанное, монотонен, не меняется от `clear()`.
- **`net_reader` (переделка 4 тестов)**: `icy_blocks_are_stripped_and_track_updates` (`tests/net_reader.rs:593`), `icy_track_changes_with_blocks` (`:668`), `no_icy_server_plays_plain_stream` (`:738`), `reconnect_reframes_icy_stream` (`:797`) — наблюдение трека переносится на «симуляция прочтения аудио до смещения + тик»: хелпер в `tests/common` читает N байтов из буфера и зовёт `tick()`.
- **`net_reader` (новые)**: трек не публикуется до прочтения аудиоблока (недобор); публикуется после прочтения до смещения; краткий обрыв без очистки — смена доезжает по звуку; мусорное переподключение с очисткой — ожидающие смены не публикуются.
- **`cli_mock`** (`tests/cli_mock.rs:235–249`): headless-печать появляется после того, как соответствующее аудио «проиграно» моком; порядок строк «станция сразу / трек по звуку».
- **Живой прогон**: заголовок меняется в момент начала звучания трека, не при приёме (ручная проверка по чек-листу apply-фазы).

### D8: Декодирование — вне аудио-колбэка (фикс по итогам ручной проверки)
Rodio 0.23 смешивает сэмплы прямо в колбэке устройства (`stream.rs init_stream`: `samples.next()` в data-callback), а underrun-пауза `BufferReader` (`src/pipeline.rs:262–285`) блокируется до повторного предбуфера — при обрыве сети дольше ~30 с PipeWire убивает поток, сессия ложно завершается Fatal «аудиоустройство». Ремонт: тракт декодирования (probe/первый кадр — по-прежнему в конструкторе для синхронного `spec()`) уезжает в выделенный поток, кадры пушатся сэмпл-чанками в ограниченный `sync_channel` (~100 кадров ≈ 2 с); `Mp3Source` худеет до читателя FIFO: `next()` отдаёт сэмпл из текущего чанка, при исчерпании — `try_recv`: пусто → равновесный сэмпл (тишина) без блокировки, разрыв (декод-поток завершился) → `None` (Player пустеет, живой цикл классифицирует исход как раньше). Блокирующийся `send` — backpressure декодера; при остановке сессии источник отбрасывается Player'ом → приёмник dropped → send ошибкой завершает поток, утечки нет. Underrun-пауза и её флаг остаются в декод-потоке (обычный поток — блокироваться можно); `current_span_len` становится `None` (рамки кадров больше не видны источнику; rodio использует его только в опциональных обёртках, не в Player). Текст ошибки cpal логируется в error-callback `session.rs` (сейчас глотается) — настоящая причина гибели аудиопотока видна в stderr.

*Альтернатива*: «неблокирующееся чтение с возвратом тишины в декодер» — невозможно без порчи тракта: тишина попала бы в MP3-декодер как байты потока. Ограниченный таймаут вместо бессрочной паузы — колбэк всё равно блокируется на таймаут; PipeWire убивает быстрее надёжного возобновления. Обе отклонены.

**Позиция звучания после FIFO.** Декодер с FIFO бежит впереди звука на его заполнение (~2,4 с при 100 кадрах): дренировать ворота по `total_read` декодера — снова опережать звук (поймано живым прогоном: строка трека появлялась до «Воспроизведения»). Решение: каждый чанк FIFO несёт метку `read_end` — позицию чтения тракта после декодирования этого кадра; потребитель сэмплов при исчерпании чанка ставит её в атомик `sound_pos` (один store на чанк, ~40/с, не на сэмпл; тишина позицию не двигает), и ворота дренирует `tick()` по `sound_pos`. Ёмкость FIFO на синхронность теперь не влияет. Финальный чанк метит свою позицию на Disconnected — потребитель догоняет тракт к концу потока.

**Пейсер чтения (устранение находок ревью P1, hunter+oracle).** Метки `read_end = ring.total_read()` несут упреждение bulk-чтения `MediaSourceStream`: его refill тянет блоки с удвоением до 32 КиБ, `total_read` прыгает на блок разом — метки всех кадров блока указывают в его конец, заголовок опережал бы звук до ~1,5 с (не ловится мок-тестами: их чтение и есть потребление). Лечение: `PacedReader` между `BufferReader` и symphonia режет `read` до 2 КиБ (`PACED_READ_BYTES`); короткие чтения легальны, MSS честно берёт `actual_read_len`, упреждение меток ≤ ~2 КиБ ≈ 90 мс. Регрессионный тест на настоящем тракте (`metablock_publishes_by_sounding_not_by_decoder_readahead`): публикация по звучанию + верхняя граница метки (звучащее + литеральные 8 КиБ — бюджет не кратен константе пейсера, иначе проверка сама раздувается при его отключении).

### D9: Тесты фикса
- **Юнит `pipeline`**: голод FIFO — `next()` отдаёт равновесные сэмплы без блокировки (замер времени на пачку вызовов); закрытие буфера — декод-поток завершается, `next()` после исчерпания FIFO возвращает `None`; исход читается из слота `SharedOutcome` (геттеры `outcome`/`packets` остаются на стороне тракта).
- **Существующие тесты `pipeline`**: итерация источника до `None` + исход из слота — механика та же, правка точечная.
- **Живой повтор ручной проверки**: обрыв сети ~40 с → «Буферизация», заголовок замирает; возврат сети → звук и заголовок возобновляются, Fatal нет.

## Risks / Trade-offs

- [Упреждение меток bulk-чтением MSS (0–32 КиБ ≈ до 1,5 с) — заголовок опережал бы звук] → устранено пейсером чтения (D8), упреждение ≤ ~2 КиБ ≈ 90 мс + буфер устройства rodio (десятки мс); оба в допуске 0,5 с, регрессионный тест держит верхнюю границу.
- [`Relaxed`-порядок атомика: дренаж видит позицию с опозданием на опрос] → ограничено 100 мс, в допуск укладывается с запасом.
- [Долгий обрыв: смена трека не догоняет, заголовок держит последний показанный трек] → самолечивается первым метаблоком нового соединения (аудио нового соединения дренирует его сразу).
- [Переделка 4 стабильных тестов `net_reader` — самый тяжёлый пласт] → хелпер симуляции чтения один на все тесты; сценарии каждого теста сохраняются, меняется только момент наблюдения.
- [Тик стал писателем `now_playing.track` (раньше писал только reader-поток)] → все записи под одним мьютексом `NowPlaying`; порядок локов зафиксирован в D4, циклов нет.
- [Сэмпл-FIFO добавляет до ~2 с буфера между декодером и звуком] → синхронности не вредит (метки едут с чанками, дренаж по `sound_pos`); растёт только общая задержка эфира относительно сети, для радио несущественно.
- [`is_underrun` после D8 — признак паузы декодера, не звука] → «Буферизация» появляется на ≤2,4 с раньше фактической тишины, пока FIFO доигрывает; принято (ошибка в раннюю сторону, тема статусов отложена пользователем), комментарии актуализированы.
- [Мусорное переподключение: хвост старой эпохи в FIFO (≤100 кадров) звучит после сброса ворот] → заголовок отстанет от звука ≤2,4 с только на этом переходе, следующим метаблоком выправляется; сброс FIFO усложнил бы тракт — принято.
- [Ёмкость FIFO во времени станциезависима: 1152-сэмпловые кадры ≈ 2,4 с @48 кГц / 2,6 с @44,1 кГц, MPEG2/2.5 (576 сэмплов) ≈ 1,2 с] → на синхронность не влияет (метки едут с чанками), влияет только на jitter-запас декодера; ~1 МиБ памяти на сессию — принято.
- [Аллокация `Vec` на каждый кадр (`mem::take` отдаёт capacity с чанком)] → прежний комментарий «аллокаций нет» снят; ~40 аллокаций/с по ~4–8 КиБ — копеечно, переиспользование потребовало бы пула — не принято.
- [`try_recv` (мьютекс std::mpsc) в RT-колбэке устройства] → критсекция крошечная, rodio сам так делает (queue); инцидентов в живых прогонах нет, косвенный контроль — error-callback с текстом ошибки.
- [Запись со смещением 0 публикуется нулевой позицией до первого байта звука] → шум одного чанка ~26 мс, семантика «до первого аудиобайта»; зафиксировано тестом `drain_ether`, чтобы инициализацию «не починили» наоборот.
- [Рассинхрон шкал записи/чтения после `clear()` ≤ внутреннего буфера MSS (security#2, LOW)] → первый метаблок нового соединения публикуется с задержкой до ~3 с звука; редкий путь (мусорный реконнект), самолечится, одна шкала потребовала бы пересчёта смещений — не принято.
- [Голод FIFO отдаёт тишину порциями семпла] → равновесный сэмпл (ноль для f32) побайтово; переходы к тишине и обратно не щёлкают заметнее прежнего поведения устройства при underrun.
- [Декод-поток переживает сессию?] → нет: источник уезжает в Player, `player.stop()` отбрасывает источники → приёмник FIFO dropped → `send` возвращает ошибку → поток завершается; утечки нет.
- [Паника `refill` в декод-потоке не покрыта тестом] → на crafted-данных symphonia воспроизвести панику по требованию нельзя; ветка — 6 строк, зеркало проверенного catch конструктора; принято как задокументированная дыра.

## Migration Plan

Один атомарный коммит: кольцо + гейт + дренаж + переделанные тесты. Откат — revert коммита, внутренних промежуточных состояний нет. Для пользователя изменение мягкое: заголовок начинает меняться на заполненность буфера позже, чем раньше; новых настроек и интерфейсов нет.
