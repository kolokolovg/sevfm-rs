# Design

## Context

Сейчас имя сервиса-источника живёт только внутри воркера обложек: `search_cover` возвращает `(Service, url)` ([cover.rs:808](../../../src/cover.rs)), но наружу уходит `CoverImage` с голыми пикселями и `CoverReply::Found(image)` — источник теряется. Кеш хранит сырой JPEG CDN (`<sha256>.jpg`) без метаданных, поэтому при повторном треке источник неоткуда взять. Окно получает обложку байтами (`SharedPixelBuffer`), MPRIS отдаёт `file://` на файл кеша. Мотивация — в proposal.md.

## Goals / Non-Goals

**Goals:** донести источник до окна с учётом кеш-хитов; рисовать ватермарк только в окне.

**Non-Goals:** ватермарк в MPRIS/кеше (не запекаем в картинку — см. D7); логотипы сервисов; настройка вкл/выкл; миграция старого кеша (записи без источника легальны — спека album-art).

## Decisions

### D1. Источник — поле `CoverImage`, а не новый вариант ответа

`CoverImage` получает `pub source: Option<Service>` (enum `Service` становится `pub`); `CoverReply::Found(CoverImage)` не меняется.

Почему не `Found(CoverImage, Service)`: источник обязан доезжать и из кеш-хита (`read_cached`), где `Service` восстанавливается, а не известен заранее; поле в `CoverImage` — общий знаменатель обоих путей, а изменение сигнатуры `Found` ломало бы все match-паттерны тестов (`CoverReply::Found(_)`). `None` — обложка без источника (старый кеш, повреждённый sidecar).

### D2. Sidecar-файл `<key>.src` с машинным именем сервиса

Источник в кеше — отдельный файл `<sha256-ключ>.src` рядом с jpg, содержимое — стабильное машинное имя: `discogs` / `itunes` / `deezer` / `yandex`. Парсинг обратно в `Service`; неизвестное или нечитаемое — `None`, не ошибка (деградация спеки album-art). Запись — в `write_cached` (новый параметр `service`) тем же паттерном `.{key}.{pid}.tmp` + rename: атомарно и безопасно при параллельных экземплярах, осиротевший tmp подчистит существующий `sweep_stale_temp_files`. Чтение — в `read_cached` после успешного декода jpg.

Альтернативы отвергнуты: встраивание в JPEG-метаданные — image crate не пишет EXIF/XMP в JPEG; кодирование сервиса в имя файла (`<key>.<service>.jpg`) — ломает существующие записи и `cached_cover_path` для MPRIS `artUrl`; отдельный индекс-файл/БД — overkill для 1 строки на запись.

Защита чтения (находки ревью): перед чтением — lstat-проверка «обычный файл, не симлинк» и лимит 32 байта (паттерн `touch_last_used`) — подброшенный гигантский sidecar или симлинк на `/dev/zero` не вешает воркера; трим входа — внутри `from_machine_name` (единственная точка). Неудача записи sidecar снимает цель best-effort: «без источника» честнее ложного имени осиротевшего файла.

### D3. Sidecar — часть записи кеша: удаляется вместе с jpg, размер не считается

`enforce_cache_limit` снимает пару `key.jpg` + `key.src` общим хелпером в обоих засчитываемых исходах удаления жертвы — успех и «уже нет» (параллельный экземпляр): без этого ветка NotFound оставляла осиротевший `.src` (находка ревью P2 — конфликт со сценарием спеки). Размер sidecar (≈10 байт) не входит в учёт лимита — не усложняет сбор записей, погрешность ничтожна против 100 МиБ. `read_cached` при удалении повреждённого jpg удаляет и sidecar. `clear_cover_cache_in` включает `*.src` в условие удаляемых файлов. Осиротевший `key.src` без jpg (обрыв между двумя удалениями) безвреден — не читается без jpg — и уйдёт с `--clear-cache`; погони за ним в вытеснении нет.

### D4. Отображаемое имя — существующий `Service::name()`

Ватермарк показывает то же имя, что и лог: «Discogs», «iTunes», «Deezer», «Яндекс.Музыка». Отдельный список «коротких» подписей отвергнут — два списка имён разойдутся; самое длинное имя (13 симв.) влезает в плашку на карточке 350×350.

### D5. UI: свойство `cover-source` + условная плашка внутри карточки

`in-out property <string> cover-source` (дефолт `""` = плашки нет). Плашка — `Rectangle` c `Text` внутри существующей карточки обложки (её `clip: true` корректно режет плашку скруглением), условный элемент `if cover-source != ""`: правый верхний угол, отступ 8px от краёв. Стиль: фон `rgba(11, 13, 19, 0.6)` — тот же тёмный тон, что фон окна и градиент (единая палитра), белый текст 12px, радиус 8px, внутренние отступы 4×8px. Альтернатива «голый текст с тенью» — читаемость на светлых обложках нестабильна; полупрозрачная плашка читаема на любых. Стиль выбран пользователем по мокапам на реальных обложках из кеша (2026-11-16: плашка 60% против той же плашки 35% и голого текста с тенью — последний тонет на светлых фонах). Тонкая подстройка вида — ручная приёмка.

### D6. Связка: источник гасится во всех точках заглушки

`Found(image)` → `set_cover_source(source.map(name).unwrap_or(""))`. Каждая установка заглушки дублируется `set_cover_source("")`: старт приложения, сброс и неудачный старт сессии (main.rs:191, 202), мёртвый воркер (804), не-музыка (811), промах `Miss` (836). Пропущенная точка = «залипшая» плашка чужого трека — митигировано сценарием «Смена трека» спеки player-ui и ручным чек-листом.

### D7. Не запекать ватермарк в картинку

Ватермарк — элемент окна поверх `Image`; байты обложки (SharedPixelBuffer, файл кеша, MPRIS `artUrl`) не меняются. Кеш не инвалидируется, MPRIS-виджет KDE показывает чистую обложку, смена вида плашки не требует перезакачки.

## Risks / Trade-offs

- [Пропущена точка сброса — плашка «залипла» на заглушке] → все точки перечислены в D6; сценарий спекы; ручная приёмка.
- [Обрыв между удалением jpg и sidecar — осиротевший `.src`] → безвреден (не читается без jpg), удаляется `--clear-cache`; принят как 10 байт мусора.
- [Старый кеш без sidecar навсегда без ватермарка] → кеш-хит не перезаписывает запись; разрешено спекой (обложка без источника), уйдёт при вытеснении/очистке.
- [Обрыв между rename jpg и rename sidecar — jpg нового сервиса + `.src` старого, плашка наврёт] → вероятность низкая (пере-фетч живой записи другим победителем цепочки и обрыв именно между двумя rename); урон — неверная подпись до перезаписи записи. Принято как риск; атомарность пары файлов ФС не даёт, усложнение (единый контейнер/порядок) не окупается.
- [Смена `Service`-имён в будущем разъедется с sidecar] → машинные имена (`discogs`…) стабильнее человекочитаемых; неизвестное значение уже легально = `None`.

## Migration Plan

Не требуется: формат кеша обратно совместим (старые записи читаются, новые получают `.src`; никакие файлы не переименовываются и не удаляются при обновлении). Откат — просто предыдущая версия: `.src`-файлы игнорируются.
