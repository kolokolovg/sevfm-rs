# Design

## Context

Плеер уже имеет потоковый воркер внешних запросов — воркер обложек `src/cover.rs`: транспорт-trait `CoverHttp` + продакшн `UreqCovers` (таймауты, лимиты тела, ручные редиректы) + тестовый `FakeHttp`, дисковый кеш с лимитом и LRU-вытеснением (`read_cached`/`write_cached`/`enforce_cache_limit`), sidecar-файл источника `.src`, воркер-поток с каналами `Request`/`Reply` и неблокирующим `poll_reply` из poll-тика Slint (`main.rs`), guard смены трека через сверку запроса. Текущее состояние трека доходит до воркера через `covers.track_changed(...)` в `main.rs`. Состояние UI собирается в `PlayerView::poll` (`src/ui.rs`) и пишется в окно через `window.set_*`.

HTTP-стек — ureq 3.5 + rustls, новых зависимостей не требуется. Спека `player-ui` фиксирует кадр 440×560 (`min = max = preferred`), композиция — абсолютное позиционирование внутри окна; `GlassButton` имеет disabled-вид (opacity 0.38) и формулу ширины от контента.

Мотивация и границы — в proposal.md; требования — в дельтах specs.

## Goals / Non-Goals

**Goals:**

- Модуль `src/lyrics.rs`: поиск текста, кеш, потоковый воркер — перенос устоявшихся паттернов `cover.rs`.
- Доставка текста в окно через существующий poll-цикл без блокировок и без новых потоков коммуникации.
- Панель текста и кнопка «Т» в окне; зависимость ширины кадра от состояния панели.

**Non-Goals:**

- Синхронизация текста по времени эфира (подсветка строки, проводка позиции от EtherGate) — снято пользователем.
- Дополнительные источники текстов (кроме LrcLib), поиск по album/duration, кеш в памяти.

## Decisions

**1. Один источник LrcLib: точный `/api/get`, затем поисковый fallback (D13).**
Живая проба (2026-11-20) показала 17/19 прямых попаданий; два промаха («Сансара», «Беловежская пуща») — записи отсутствуют в базе вовсе. Приёмка 5.3 (2026-11-22) показала обратную сторону строгого get: дуэты и саундтреки с пометками в титуле теряются при живой записи в базе — добавлен поисковый fallback (решение 13). `instrumental=true` трактуем как «текста нет» (у конкретной записи; fallback ищет по той же базе).

**2. Транспорт — зеркальный перенос паттерна обложек.**
`trait LyricsHttp { get(url, лимит тела) -> статус + тело }` + `UreqLyrics` (агент с `max_redirects(0)`, `https_only` — не-https отклоняется, как у обложек; URL хардкод https) + тестовый `FakeHttp`. Статус в ответе транспорта появился с D13: 404 точного запроса — штатный промах и сигнал fallback'а, не ошибка. Таймауты как у `UreqCovers` (соединение/ответ/чтение 5 с, тело 15 с); лимиты тела раздельные (находка hunter-ревью): точный запрос 1 МиБ — живые ответы 13–17 КиБ, запас более чем 60-кратный; поиск 4 МиБ — массив кандидатов несёт и неиспользуемые synced-тексты (живая проба ~50 КиБ, длинные треки сотни КиБ; единый лимит называл честный большой ответ «мусором»). UA `sevfm/<version>` — тот же формат.

**3. Кеш текстов — отдельный каталог, формат и вытеснение как у обложек, масштаб 1/10.**
Каталог `$XDG_CACHE_HOME|~/.cache/sevfm/lyrics`. Ключ — sha256 от `artist\ntitle`: сняты trim, регистр и пометки в скобках титула (`query_title`) — единая нормализация с URL запроса; иначе вариации написания ICY между звучаниями (капс, «;»-дуэты, скобочные пометки) плодили бы сетевые запросы и записи кеша (находки hunter/oracle-ревью). Запись: `<key>.txt` с текстом + sidecar `<key>.src` с именем источника (лимит 32 байта) — переиспользование sidecar-паттерна обложек. Лимит 10 МиБ (средняя запись ~15 КиБ → сотни текстов), вытеснение LRU по `touch_last_used`, recheck-гистерезис 0.5 МиБ. Повреждённая запись — промах с перезаписью при удачном поиске.

**4. Воркер — тот же каркас mpsc, состояние через `poll_reply`.**
`Lyrics { start(), with_backend(...), track_changed(artist, title), poll_reply() -> Option<LyricsReply>, is_dead() }`. `LyricsReply::{Found { text, source }, Missing}`; guard смены трека — ответ несёт свою генерацию, свежесть сверяет потребитель при дренировании `poll_reply`: все bump'ы генерации идут из потока цикла событий, поэтому сверка атомарна и закрывает ответы, уже лежащие в канале (перенос находки ревью обложек — TOCTOU «проверил-и-отправил» в воркере неустраним). Слот текста (`LyricsSlot`: `Searching | Found { текст, источник } | Missing`) живёт в `PlayerView` — текст приходит от воркера, а не от снимка сессии, поэтому дедуплицируется отдельно (`update_lyrics`); из него — флаг активности кнопки «Т» и содержимое панели. В headless воркер не запускается (как обложки).

**5. Кадр окна — выражение от свойства панели, без перестройки композиции.**
В `player-window.slint` ширина кадра (`preferred/min/max-width`) становится выражением от `in-out property <bool> panel-open`: 440px или 880px. Композиция обложки остаётся в левой 440-полосе (absolute), панель — отдельный прямоугольник при `panel-open` на `x: 440px`, фон-подложка `#10131c`. Альтернатива через `HorizontalLayout` отклонена: риск циклов ширины уже ловили в этом файле (урок `GlassButton`). `panel-open` — состояние Rust (`UiBinding.panel_open`), клик «Т» — callback в Rust, Rust пишет свойство — единый владелец состояния, как у всех данных окна.

**6. Кнопка «Т» — параметр `square` у `GlassButton`, не новый компонент.**
Один стиль, минимальный diff: `in property <bool> square: false` → ширина 44px вместо формулы от контента, текст без иконки. Disabled-вид уже есть (`opacity 0.38`).

**7. `--clear-cache` очищает оба кеша, флаг не трогаем.**
`clear_lyrics_cache()` рядом с `clear_cover_cache()`; вывод — суммарный объём. Разбор аргументов не меняется.

**8. Живой тест источника — с env-гейтом, юниты — на `FakeHttp`.**
`tests/lyrics_live.rs` (по образцу `mpris_live.rs`): реальный LrcLib на известном треке, кириллическом и гарантированном промахе; прогон вручную перед ревью (правило живых тестов), в CI не обязателен. Юниты: поиск/промах/инструментал/кириллица/смена трека/кеш/лимит/таймаут/гигантское тело/очистка двух кешей.

**9. Артист из метаданных нормализуется: часть до первой «;»** (предложение приёмки 5.3, 2026-11-22; гипотеза проверена живьём).
ICY эфира несёт нескольких артистов через точку с запятой («СЕРГЕЙ ТАЮШЕВ;ТАТЬЯНА РУЗАВИНА»). Живая проверка показала: LrcLib обычно прощает полную строку — `Кино;Виктор Цой → 200` с полным текстом (база знает вариант «Кино (Виктор Цой)»); промах «Станции минутки» (404 и по чистому «СЕРГЕЙ ТАЮШЕВ») — отсутствие записи, не разделитель. Нормализация оставлена как предосторожность и унификация: `primary_artist` — единая точка для URL запроса и ключа кеша («А;Б» и «А» идут в одну запись); диагностика промаха печатает нормализованный запрос, сырая строка эфира видна в записи «эфир:» того же тика.

**10. Версия сборки в заголовке окна** (просьба приёмки 5.3).
Свойство `app-version` пишет Rust — Slint окружение не читает. Формат: «{станция} — {версия}», версия пакета; debug-сборка помечена суффиксом `-dev`, чтобы приёмку не путать с релизным бинарником. Имя приложения в хвост не входит (правка приёмки: «только версию»).

**11. Прокрутка текста перетаскиванием** (просьба приёмки 5.3).
`ScrollView` по умолчанию глушит drag-pan (`mouse-drag-pan-enabled: false` зашито во fluent-виджете) — прокрутка только колесом. Для панели текста включено: зажать кнопку мыши на тексте и тянуть — содержимое следует (семантика touch-скролла Flickable), колесо продолжает работать. Спека «Прокрутка длинного текста» не меняется — способ ввода не предписан.

**12. Панель закрывается, когда у нового трека текста нет** (находка приёмки 5.3 — «логично было бы свернуть это окно»).
Первоначальная спека давала тупик: панель сохранялась при смене трека, а кнопка «Т» активна только при найденном тексте — открытая пустая панель с неактивной кнопкой несводима пользователем. Правило финальное: Searching (поиск идёт) — панель остаётся пустой; Missing — панель закрывается, окно сжимается; Found — панель остаётся с текстом. Спека player-ui обновлена (сценарий «Текста у нового трека нет»), `set_lyrics_view` принимает связку и гасит панель на Missing.

**13. Fallback поиска `/api/search` с клиентским выбором кандидата** (находка приёмки 5.3, 2026-11-22).
Живой случай: ICY «АНАТОЛИЙ ГОРОХОВ;ОЛЕГ АНОФРИЕВ — Песня друзей (м,ф Бременские музыканты)» — точный get 404, хотя запись в базе жива («Олег Анофриев / Анатолий Горохов», титул без пометки); `/api/search` по названию находит сразу. Механика: после промаха get — поиск по названию **без артиста** (живая проверка: артист в query сужает поиск мимо записей с иным написанием); пометки «(...)» из титула срезаются и в запросе, и при сравнении; выбирается кандидат с совпавшим нормализованным названием двухпроходно (находки hunter/oracle-ревью): сначала точное равенство множеств токенов артистов (оригинал), затем вложение в любую сторону — иначе кавер-версия с неполным множеством, стоящая выше оригинала в ранжировании API, перехватывает текст; пустое множество токенов (мусорный артист эфира, запись без артиста) не совпадает ни с чем. Порядок, регистр и разделители дуэтов не важны: «ГОРОХОВ;АНОФРИЕВ» ≡ «Анофриев / Горохов»; скобки в артисте сохраняются — «Кино (Виктор Цой)» это второй артист. Инструментальные, пустые кандидаты и записи без артиста пропускаются. Спека lyrics обновлена (сценарий «Дуэт с другим написанием в базе»).

## Risks / Trade-offs

- [Slint может не применить изменение `min/max/preferred-width` у живого окна в KWin] → проверить в apply на живом окне; запасной путь — программная установка размера из обработчика toggle. Точечная правка, требования не меняются.
- [Расширение кадра ломает приёмочные ожидания «единственного кадра»] → дельта `player-ui` обновляет требование; ручной чек-лист пользователя обязателен (видимая поверхность).
- [Точный `/api/get` промахивается на кривых именах из ICY там, где search нашёл бы] → принято как trade-off (Decision 1); расширение — отдельный change, если живая эксплуатация покажет частые промахи.
- [Трек сменился во время запроса] → guard сверки запроса, как у обложек; опоздавший ответ отбрасывается.
- [Отказ воркера текста] → состояние «текста нет», воспроизведение не затронуто (требование «Отказы текста не влияют на воспроизведение»); диагностика аналогично обложкам.

## Migration Plan

Миграции данных нет: каталог кеша текстов новый, создаётся при первой записи. Откат — реверс коммита; `--clear-cache` продолжает работать на обложках в старых версиях.

## Open Questions

Нет: пользовательские решения (вариант А, plain, кнопка-«Т» toggle, disabled без текста) зафиксированы на утверждённых мокапах; оставшееся — отложенная альтернатива в Non-Goals, не вопрос.
