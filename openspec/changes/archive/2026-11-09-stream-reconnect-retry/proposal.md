# Proposal

## Why

При обрывах сети клиент после серии ретраев может получить на повторное соединение HTTP-ответ 3xx/4xx (перезапуск icecast, временно пропавший маунт, ответ узла цепочки прокси). Сегодня такой ответ классифицируется как перманентный отказ: сессия умирает, UI показывает красную рамку «подключение отклонено сервером», ретраи прекращаются. При этом URL заведомо рабочий — сессия уже играла, — отказ носит транзиентный характер, и пользователю приходится перезапускать воспроизведение вручную после каждого такого случая.

## What Changes

- На повторных соединениях сессии после первого соединения, доставившего данные, любой статус отклонения (HTTP 3xx/4xx, включая уже повторяемые 408/429) уходит в штатную лестницу backoff переподключения (1→2→5→10 с, без лимита попыток) — как сетевые ошибки; сессия продолжает жить, UI остаётся в «Переподключении»/«Буферизации», красная рамка не появляется.
- На соединениях до доставившего данные семантика не меняется: 3xx/4xx кроме 408/429 — перманентный отказ с завершением сессии (быстрая диагностика неверного URL/маунта: headless — ненулевой код, UI — красная рамка).
- Отклонение на переподключении логируется в stderr с HTTP-кодом в общем формате неудачной попытки («подключение не удалось: стрим недоступен: HTTP {код}»), без формулировки «повторение бессмысленно».

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `audio-pipeline`: требование «Ошибки запуска» — перманентный отказ сервера завершает сессию только на соединениях до первого доставившего данные; статусы отклонения на соединениях после доставившего данные приравниваются к сетевым ошибкам и повторяются с задержкой.
- `player-ui`: требование «Фатальные ошибки сессии в UI-режиме» — красная рамка «подключение отклонено сервером» показывается только при отклонении до доставившего данные соединения сессии; отклонения при переподключении не фатальны.

## Impact

- Код: `src/net.rs` — условие фатальности `StreamError::Status` в `reader_loop` (сейчас `net.rs:602-625`); граница «первое соединение vs переподключение» — существующий флаг `ReaderState::had_connection` (`net.rs:511`, устанавливается первым прочитанным байтом `net.rs:767`).
- Тесты: интеграционные `tests/net_reader.rs` — сценарии «отказ после доставившего данные соединения → повтор»; юнит-тесты классификации, если затронуты.
- Спецификации: дельты `audio-pipeline`, `player-ui`.
- Не меняется: коды выхода headless, `classify()` в `session.rs`, механика красной рамки в UI, лестница backoff, поведение 408/429 на первом соединении, поведение сетевых ошибок и 5xx.
- Решение заменяет часть D4 change `harden-network-resilience` («остальной 3xx/4xx — перманентный отказ») для повторных соединений; для первого соединения D4 сохраняется.
