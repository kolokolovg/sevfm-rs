# Design

## Context

Фаза 1 порта (см. proposal.md — Why). Главный спек `radio-player` требует непрерывности: чтение потока в ограниченный буфер, воспроизведение из буфера «а не напрямую из сети», переподключение при обрывах. PoC-итерация фазы 1 читала сеть прямо в потоке вывода; ревью четырьмя субагентами подтвердило по вендоренным исходникам два фатальных дефекта этого подхода:

- **P0**: неограниченный ресинк-цикл symphonia (`read_mpeg_frame`/`sync_frame` без бюджета байтов) при вечном мусоре: процесс не завершить по SIGINT/SIGTERM — drop аудио-устройства делает `join()` аудио-потока (cpal ALSA `Stream::drop`) и ждёт вечно;
- **P1**: SIGINT при сетевом простое — выход задерживается до таймаута чтения (30 с) тем же `join()`.

Вывод: развязка сети и вывода — не «фаза 2», а условие исполнимости спеки. Сетевые ограничения машины разработки: TLS до Cloudflare/Fastly дропается провайдером; доступные источники — напрямую или через HTTP-прокси `127.0.0.1:10809`; `static.crates.io` может не отвечать — качающийся cargo уметь пускать через прокси (D7).

## Goals / Non-Goals

**Goals:**

- Непрерывное воспроизведение живого HTTPS-MP3-стрима: reader-поток → кольцевой буфер → декод → PCM-вывод.
- Перенос поведения устойчивости: sync-поиск с середины кадра, пропуск битых кадров, мусорный бюджет → переподключение.
- Переподключение с нарастающей задержкой при обрывах; звук из буфера не прерывается; долгий обрыв — пауза с авто-возобновлением.
- Мгновенный (≤ 1 с) выход по SIGINT/SIGTERM без зависаний; коды выхода 0/2.
- Аудио-стек порта зафиксирован с лицензионной записью (сделано в PoC-итерации).

**Non-Goals:**

- ICY-метаданные, UI, трей, обложки (последующие фазы).
- Кросс-компиляция (фаза упаковки).
- Тонкая настройка латентности: параметры буфера выбраны заново и подлежат замеру живьём.

## Decisions

### D1: HTTP-клиент — `ureq` (синхронный)

Тело ответа — `Read`, читается по мере поступления. TLS — rustls с корнями webpki (дефолт). `Accept-Encoding` отключается: радио-MP3 не сжимается, gzip здесь только лишняя поверхность. HTTP/2 не нужен. Alternative: `minreq` — легче, но менее battle-tested.

### D2: MP3-декодер — `symphonia` напрямую

Стриминговый probe → формат-ридер → покадровый `next_packet`/`decode`; контроль ошибок на уровне кадра. Лицензия MPL-2.0 — записана в THIRD-PARTY-NOTICES. Известная особенность (по ревью): ресинк-циклы демуксера не ограничены — ограничиваем сами мусорным бюджетом (D5). Alternative: `minimp3` — запасной план при проблемах symphonia на мусорном старте.

### D3: Аудиовыход — `rodio` (DeviceSink + Player)

Player/микшер конвертируют формат источника в формат устройства — «параметры из потока» без ручной настройки линии. Контракт `Source`: `current_span_len` возвращает полный размер текущего кадра, не остаток (иначе `Some(0)` на межкадровой границе нарушает контракт «`Some(0)` ⇔ данных нет»). Alternative: cpal напрямую — отложено до потребности.

### D4: Развязка сети и вывода — reader-поток + кольцевой буфер (в фазе 1)

```
src/net.rs      reader-поток: open_stream (D1) → цикл записи в буфер;
                обрыв или мусорный бюджет → backoff → переподключение;
                флаг остановки → квантованное чтение (D5), выход потока,
                сокет закрывается drop'ом
src/buffer.rs   кольцевой буфер: блокирующие запись/чтение с таймаутом,
                предбуфер-порог, close() с разблокировкой сторон
src/pipeline.rs Mp3Source: декод (D2) из буфера; underrun → пауза
                до повторного достижения предбуфера
src/main.rs     CLI, сигналы, статусы в stderr, коды выхода, exit(0)
```

- **Backpressure**: буфер полон → writer блокируется на свободном месте; сетевое чтение естественным образом приостанавливается (TCP-окно).
- **Мусорный бюджет**: общий счётчик байтов от последнего валидного кадра (декодер сбрасывает его после каждого успешного кадра); превышение бюджета → reader закрывает соединение, **очищает буфер** и переподключается с диагностикой — мусор мёртвого соединения не сшивается со свежим потоком (то же делает лимит 50 decode-ошибок). Ограничивает неограниченные ресинк-циклы symphonia (P0) и бесконечную загрузку мусора.
- **Активация бюджета первым сбросом декодера**: до первого декодированного кадра бюджет соединение не рвёт — на быстром соединении reader успевает записать больше бюджета раньше первого decode-Ok, и без этого обрыв был бы ложным. Стартовую мусорность ограничивают probe symphonia (1 МиБ), лимит фазы первого кадра (4 МиБ/30 с, D8) и лимит ошибок декодера (50 подряд).
- **Числовые параметры** (выбраны заново; замерить живьём и тюнить):

| Параметр | Значение | Обоснование |
|---|---|---|
| Ёмкость буфера | 512 КиБ | ≈ 26 с аудио при 128 кбит/с — переживает обрыв с полной backoff-лестницей; доли процента от цели «десятки МБ RSS» |
| Предбуфер | 64 КиБ | ≈ 4 с — старт в SLO «≤ 10 с» с запасом на джиттер; тот же порог — возобновление после underrun |
| Backoff переподключения | 1 с → 2 с → 5 с → далее 10 с | быстрые первые повторы ловят «моргания» сети, редкие глубокие — лежачий сервер; потолок 10 с, чтобы пауза не тянулась дольше нужного |
| Мусорный бюджет | 256 КиБ | ≈ 16 с потока без единого распознаваемого кадра; на живом радио кадры каждые ~24 мс — ложных срабатываний нет |
| Минимальная скорость соединения | 20 КиБ за 10 с | «капающий» сервер (байты есть, звука не будет) не держит соединение вечно — спека запрещает бесконечный прогресс-фри цикл; 2 КиБ/с ниже самого экономного голосового MP3 (32 кбит/с); чистое молчание остаётся за no-progress-таймаутом 30 с |
| Таймауты resolve/connect/заголовки/read | 5 с / 10 с / 10 с / 30 с | детект мёртвого соединения при подключении и «молчащего» сервера; resolve — до connect-бюджета (ureq начинает connect после резолва); заголовки — суммарный бюджет фазы против «бесконечного drip» |
| Выход по сигналу | ≤ 1 с | требование спеки; тест ужесточён до 1 с |

- **Тесты без сети**: локальный мок-сервер (`TcpListener`) со скриптуемыми сценариями (валидная фикстура → обрыв / мусор / молчание) — детерминированные тесты переподключения, бюджета и остановки. Edge-case'ы буфера — полный/пустой/закрытие/конкуренция.

### D5: Обработка сигналов — ctrlc + AtomicBool + немедленный exit(0)

`ctrlc::set_handler` (SIGINT + SIGTERM) выставляет `AtomicBool`. Reader-поток опрашивает флаг и закрывает сокет — блокированное чтение разблокируется. Главный поток по флагу логирует остановку и вызывает `std::process::exit(0)` **без drop аудио-устройства**: drop делает `join()` аудио-потока, который может стоять в блокированном чтении — источник P0/P1 из ревью. Аудиоустройство освобождается завершением процесса (ОС закрывает ресурсы); требование спеки выполняется, деструкторы не нужны.

**Уточнение при реализации.** Остановка reader'а сделана не «закрытием сокета по флагу» (потребовало бы расшаривания сокета между потоками), а квантованием чтения: каждое чтение ограничено таймаутом 500 мс, флаг остановки опрашивается между чтениями; при выходе из потока тело ответа уходит в `drop` — сокет закрывается им. Выход по сигналу выполняет **выделенный сторож-поток** (опрос флага каждые 100 мс → `exit(0)`): главный поток к моменту сигнала может стоять в построении тракта или открытии аудиоустройства и не обязан успевать «дойти до выхода» — сторож гарантирует бюджет ≤ 1 с независимо от того, чем занят `main`.

### D6: Структура кода

```
src/main.rs      — CLI: аргументы, сигналы, статусы в stderr, коды выхода
src/net.rs       — reader-поток: чтение, backoff-переподключение, мусорный бюджет
src/buffer.rs    — кольцевой буфер с предбуфером
src/pipeline.rs  — декод symphonia из буфера, источник сэмплов для rodio
src/lib.rs       — переносимая логика; tests/ импортирует отсюда
```

Заголовок Apache-2.0 во всех файлах. Конвенции — скилл `rust-clean-code` (контракт поведения — спека, реализация свободна).

### D7: Cargo за прокси при необходимости

Первый шаг — `cargo fetch`; при недоступности `static.crates.io` — `~/.cargo/config.toml` → `[http] proxy = "http://127.0.0.1:10809"`. В репозиторий не коммитить, отметить в README.

### D8: Лимит фазы до первого декодированного кадра

`BufferReader` (единственный `Read`-источник symphonia) считает байты и время фазы до первого декодированного кадра: **4 МиБ** и **30 с**. Первый декодированный кадр снимает лимит (флаг `FirstFrameDecoded`); превышение любого из порогов → `PipelineError::FirstFrameLimit` → код 2 «поток не распознан как MP3».

Обоснование: probe symphonia сам ограничен `max_probe_depth` (1 МиБ → `Unsupported`), но без этого лимита фаза старта не детерминирована — лестница «50 decode-ошибок подряд → переподключение → обнуление счётчика» до первого кадра бесконечна (сброс мусорного бюджета на каждом распознанном заголовке мусора усугублял: поток-«мусор с заголовками» крутится вечно). Лимит переводит «мусор вместо потока» в терминальный исход кода 2.

### D9: Наблюдатель гибели аудио-потока

Авария воспроизведения после старта не должна оставлять процесс «живым без звука». Два канала наблюдения:

- **Смерть аудиоустройства**: error-callback cpal (через builder `DeviceSink`) поднимает флаг `audio_crashed`; `main` выходит из цикла ожидания и завершает процесс с кодом 2.
- **Паника тракта декодирования**: `catch_unwind` вокруг `refill` в `Iterator::next` **и вокруг построения тракта в `Mp3Source::new`** (probe + первый кадр выполняются до первого `next`) улавливает панику symphonia на недоверенных данных и переводит её в код 2 «поток не распознан как MP3» / `Outcome::DecoderError` (аналогично паника reader'а видна через `Link` — `catch_unwind` в `spawn_reader`; гибель reader'а при построении тракта классифицируется честно как `ReaderCrashed`, не маскируясь под `EmptyStream`).

Ограничение: запасной путь открытия вывода `rodio::open_default_sink` (перебор устройств, когда builder с конкретным устройством не удался) error-callback **не принимает** — в нём авария вывода видна только как пропавший звук, наблюдаемого исхода кода 2 нет.

**Разведение исходов старта** (одной строкой): probe-fail и лимит фазы D8 → код 2 (детерминированно не-MP3); мусор ВОКРУГ валидных заголовков в живом цикле → переподключение (спека устойчивости).

## Risks / Trade-offs

- [Параметры буфера/backoff выбраны заново, без обкатки] → замер живьём (латентность старта, глубина пауз при обрывах), тюнить; значения собраны в таблице D4.
- [Конкурентный кольцевой буфер — тонкое место] → юнит-тесты edge-case'ов: полный буфер, пустой, close при заблокированных сторонах, конкуренция; детерминированные сценарии на мок-сервере.
- [Мусорный бюджет: ложное срабатывание на экзотическом потоке] → порог 256 КиБ многократно превышает межкадровый интервал живого радио; срабатывание лечится переподключением, не завершением.
- [exit(0) без деструкторов] → освобождение ресурсов процессом ОС; для аудио-устройства и сокета это штатно; принято сознательно против join-зависаний.
- [cpal/ALSA против PipeWire] → живой прогон; при проблемах — конфигурация вывода через env.
- [Ограничение ureq: `timeout_per_read` (500 мс, D5) капирует и фазу ожидания заголовков ответа] → одиночная пауза > 500 мс перед заголовками рвёт попытку → штатный ретрай с backoff; суммарный бюджет фазы заголовков 10 с исключает «бесконечный drip». Разделить интервалы тела и заголовков конфигом ureq нельзя (проверено по исходникам 3.5); альтернатива — кастомный Transport, отвергнута как избыточная для фазы 1.

## Migration Plan

Модуль PoC-итерации (`pipeline.rs` с прямым чтением сокета) перестраивается на чтение из буфера; `open_stream` переиспользуется в reader-потоке; тесты PoC (фикстура, мусор, лимит ошибок, старт посреди кадра) сохраняются. Откат — возврат к PoC-структуре.
