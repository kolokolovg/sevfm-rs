# Proposal

## Why

Фаза 1 плеера sevfm на Rust + Slint (фаза 0 «скелет» завершена). Аудио-тракт — самая рискованная часть проекта, и связку «HTTP-стрим → покадровый MP3-декод → вывод PCM» нужно проверить на живом потоке до остальных слоёв.

PoC-итерация фазы 1 (сеть → декод → вывод напрямую, без развязки) проведена и отревьюена: чтение сети в потоке вывода дало два фатальных дефекта — неубиваемый по SIGINT/SIGTERM процесс при вечном ресинке декодера (drop аудио-устройства ждёт блокированный аудио-поток) и задержку выхода до 30 с на сетевом простое. Главный спек `radio-player` при этом требует непрерывности: «читать поток в ограниченный промежуточный буфер и воспроизводить звук из этого буфера, а не напрямую из сети», при обрыве — «звук не прерывается… восстанавливает соединение с повторными попытками». Поэтому фаза 1 доводится до полного тракта с непрерывностью.

## What Changes

- Бинарник `sevfm` непрерывно воспроизводит живой MP3-стрим (`https://sevfm.ru:9006/govsev`): чтение сети в выделенном потоке, ограниченный кольцевой буфер с предбуферизацией, покадровый декод и вывод PCM из буфера.
- Переподключение при обрывах соединения и при стойком мусоре с нарастающей задержкой; звук не прерывается, пока в буфере есть данные; долгий обрыв — пауза с автоматическим возобновлением после наполнения буфера.
- Устойчивость к повреждённым данным: радиопоток начинается посреди кадра — первый sync-маркер ищется автоматически; повреждённые кадры и мусор между кадрами пропускаются.
- Остановка: SIGINT/SIGTERM — остановка вывода и завершение с кодом 0 в течение секунды, без зависаний.
- Коды выхода: сетевые ошибки при установке первого соединения — повторные попытки без выхода (выход — только по сигналу, код 0); не-сетевые фатальные ошибки старта (нет аудиоустройства, поток не распознан как MP3) — код 2 с диагностикой в stderr.
- Зависимости фазы 1 (ureq, symphonia, rodio, ctrlc, thiserror) зафиксированы в `Cargo.toml` и `THIRD-PARTY-NOTICES.md`.

Явно НЕ входит (последующие фазы порта): ICY-метаданные, UI, обложки, трей.

## Capabilities

### New Capabilities

- `audio-pipeline`: непрерывное превращение живого MP3-байтового потока в звук — сетевое чтение в отдельном потоке, ограниченный буфер с предбуферизацией, покадровый декод с пропуском мусора, вывод PCM, переподключение при обрывах и стойком мусоре, мгновенная остановка по сигналу и диагностика ошибок запуска. Граница «источник байтов → звук» наращивается последующими фазами (ICY, UI-состояния), а не заменяется.

### Modified Capabilities

(нет — главный спек `radio-player` описывает конечное поведение всего плеера и на этой фазе не меняется)

## Impact

- Новые модули: `src/net.rs` (reader-поток, переподключение, мусорный бюджет), `src/buffer.rs` (кольцевой буфер); `src/pipeline.rs` — декод из буфера; `src/main.rs` — CLI, сигналы, статусы, коды выхода.
- Тесты: юнит-тесты буфера и тракта; детерминированные тесты обрыва/мусора/молчания на локальном мок-сервере; живые `#[ignore]`-тесты (стрим, SIGINT ≤ 1 с); фикстура живого среза.
- `Cargo.toml` / `THIRD-PARTY-NOTICES.md` — зафиксированы (PoC-итерация).
