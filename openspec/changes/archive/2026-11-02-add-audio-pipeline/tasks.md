## 1. Кольцевой буфер (src/buffer.rs)

- [x] 1.1 Ограниченный кольцевой буфер по design D4: блокирующие запись/чтение с таймаутом, предбуфер-порог, `close()` с разблокировкой обеих сторон; ёмкость 512 КиБ, предбуфер 64 КиБ. Юнит-тесты edge-case'ов: полный буфер (backpressure), пустой (таймаут/underrun), close при заблокированных сторонах, конкурентные запись/чтение. Верификация: `cargo test`.
- [x] 1.2 Мок-сервер для тестов без сети: локальный `TcpListener` со скриптуемыми сценариями (валидная фикстура → обрыв / бесконечный мусор / молчание / не-MP3 ответ). Верификация: используется тестами 2.x–4.x детерминированно.

## 2. Сетевой reader-поток (src/net.rs)

- [x] 2.1 Reader-поток: `open_stream` → цикл записи в буфер; обрыв → backoff 1/2/5/10 с → переподключение; лог попыток в stderr с троттлингом. Тест (мок): обрыв после валидных данных → переподключение → поток продолжается. Верификация: `cargo test`.
- [x] 2.2 Мусорный бюджет (256 КиБ без распознаваемого кадра; декодер сбрасывает счётчик после успешного кадра): превышение → закрытие соединения + переподключение с диагностикой. Тест (мок): валидный старт, затем бесконечный мусор → reconnect, процесс не зависает. Верификация: `cargo test`.
- [x] 2.3 Остановка reader'а: по флагу закрывает соединение — блокированное чтение разблокируется, поток завершается быстро. Тест (мок-молчун): установка флага → reader завершается ≤ 1 с. Верификация: `cargo test`.

## 3. Тракт из буфера (src/pipeline.rs)

- [x] 3.1 `Mp3Source` читает из буфера, а не из сокета; underrun → пауза до повторного достижения предбуфера. Фикс `current_span_len` → `Some(buffer.len())` (контракт rodio `Source`: `Some(0)` ⇔ данных нет). Юнит-тесты PoC зелёные на фикстуре через буфер. Верификация: `cargo test`.
- [x] 3.2 Разделение терминальных состояний: штатный конец / буфер закрыт при остановке / ошибка декодера — без конфлатинга; при старте обрыв сети отличим от «поток не MP3» (для кодов выхода). Верификация: `cargo test`.
- [x] 3.3 Терминальные состояния источника `Mp3Source` (без reader'а, юнит-уровень): повреждённый кусок в середине фикстуры — декодер продолжает с пропуском; мусорный поток (случайные байты) и поток с валидными заголовками, но мусорными данными — терминальная диагностика после лимита 50 ошибок подряд (`Unsupported`/`GarbageStream`), не зависание. Верификация: `cargo test`.
- [x] 3.4 Мусорный лимит декодера в живом цикле — переподключение, а не завершение (спека устойчивости): связка `net::Link` (запрос переподключения + эпоха соединений), счётчик ошибок «подряд» — в рамках одного соединения, буфер очищается перед новым соединением; исходы живого цикла видимы CLI (слот исхода): ошибка декодера и смерть reader-потока — код 2. Тесты: мусорный лимит посреди валидного потока (юнит, симуляция reader'а), закрытие соединения по запросу `Link` (мок). Верификация: `cargo test`.
- [x] 3.5 Харденинг по ревью: минимальная скорость соединения (20 КиБ/10 с — «капающий» сервер переподключается), точный underrun-флаг декодера в статусе («Буферизация» — только когда звука нет), санитизация вывода (управляющие байты — на замену, userinfo URL вырезается), `open_stream` перенесён в `net.rs` (design D6, цикл net↔pipeline разорван), приватизация не-контрактных констант, единая точка пути фикстуры (`pipeline::FIXTURE_PATH`), SeqCst для флага остановки во всех точках, `#[cfg(unix)]` для kill-тестов. Верификация: `cargo test`.
