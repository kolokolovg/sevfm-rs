# Design

## Context

Трек-строка окна — два `Text` с `overflow: elide` в `VerticalLayout` карточки (`ui/player-window.slint`, строки 313/322): артист 13px/500 с letter-spacing 1.2px, название 25px/700. Окно фиксированных кадров 440/880. Дерево уже переведено на slint 1.19.0 (обновление в рабочем дереве этого же релиза), API-механика марки по нему проверена по исходникам и живой компиляцией прототипа.

## Goals / Non-Goals

**Goals:**
- Целиком показывать переполненные исполнитель и название: ping-pong прокат внутри поля, покой по центру для коротких строк.
- Нулевые изменения Rust/зависимостей/CI — всё в разметке.

**Non-Goals:**
- Бесшовный луп-скролл (текст уехал — выехал снова) — запасной путь через элемент `Timer`, если пинг-понг будет отвергнут приёмкой.
- Прокрутка статуса, ошибки, панели текста и заголовка окна — только поля трек-строки.
- Реакция на состояние воспроизведения (пауза прокрутки при «Остановлено») — поле информационное, прокат непрерывный.

## Decisions

- **Ping-pong (`direction: alternate`), а не бесшовный луп.** Альтернатива — дублированный текст и элемент `Timer` с ручным offset: заметно сложнее и бесконечно крутится даже там, где пинг-понг читается спокойнее. Если приёмка отвергнет bounce — отдельная правка на Timer-луп (механика проверена: pass lower_timers.rs в 1.19 на месте).
- **Детекция переполнения — `Text.preferred-width > ширина контейнера` при `wrap: no-wrap`.** Паттерн уже в проекте (плашка ошибки строится по `error-text.preferred-width`); preferred-width не зависит от назначенной ширины — цикла лэйаута нет.
- **Гейт анимации — `animate x { enabled: scrolling; }`.** Без него бесконечная анимация пинг-понговала бы вокруг центра и на коротких строках; `enabled: false` даёт мгновенный прыжок в центр покоя без анимации.
- **Скорость пропорциональная: `duration: max(3s, min(30s, переполнение/1px × 36ms))`** — ~28 px/с, зажата в 3–30 с на проход, чтобы длинные названия не «летели», короткие переполнения не ползли. Единицы: переполнение делится на `1px` до безразмерного и умножается на ms (проверено компилятором 1.19).
- **Компонент top-level** (`component MarqueeText inherits Rectangle` рядом с GlassButton) — вложенные component-декларации Slint не парсит (поймано минитестом); текст-ребёнок с явным `width: self.preferred-width` — элемент без явной ширины растягивается на 100% родителя (урок ватермарка), preferred-width остаётся естественной шириной строки.
- **Центровка покоя — `x: (parent.width - self.width) / 2`** от контейнера, не от `root.width` окна (урок приёмки add-lyrics-panel: центровки от parent.width при динамической ширине).
- **`overflow: clip` вместо `elide`** у прокатываемого текста — многоточие при прокрутке не имеет смысла; клипует контейнер.

## Risks / Trade-offs

- [Эстетика ping-понга на очень длинных названиях] → альтернатива Timer-луп задокументирована, замена локальна (один компонент).
- [Рывок при смене трека: анимация перенацеливается с текущей позиции] → если будет резким, сброс позиции через `changed track-title` в apply — правка одной строки; проверить на приёмке.
- [Непрерывный repaint поля на software-рендерере] → площадь — пара строк высотой в ~13–25px, тот же класс затрат, что у курсорных анимаций; плато памяти не затрагивает.
- [1.19 мог менять `preferred-width` при letter-spacing] → в прототипе artist-строка с letter-spacing 1.2px собирается и детектируется через preferred-width; финальная проверка — приёмка с длинным артистом.
