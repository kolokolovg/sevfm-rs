# Proposal

## Why

CI на GitVerse дважды упал на коммите `30ba745` (документы, продукт не тронут;
на GitHub тот же коммит зелёный): на двух разных облачных раннерах упали
**разные** тесты одного семейства — «публикация метаданных по звучащей
позиции». Раннеры GitVerse — шаренные Docker-контейнеры под нагрузкой,
а упавшие тесты строятся на предположениях о скорости планировщика потоков.
Попутно выяснено: windows-джоба никогда не стартует (в доках GitVerse заявлен
только `ubuntu-latest`) и вечно висит в waiting, `Swatinem/rust-cache` молча
не работает, дефолтный таймаут джобы 15 минут — полный прогон (~13 мин)
впритык, а месячный бюджет сборок ограничен.

## What Changes

- Тест `pipeline::tests::metablock_publishes_by_sounding_not_by_decoder_readahead`
  (`src/pipeline.rs`) переписывается на решения по **измеренному**
  `sound_pos` вместо арифметики кадров: цикл «ожидания запаса декодированных
  кадров» потребляет сэмплы, не учитывая их, — на голодном по CPU раннере
  звучащая позиция легально доходит до метаблока, и ассерт «ещё не
  опубликовано» видит опубликованный трек.
- Тест `icy_metadata_printed_to_stderr` (`tests/cli_mock.rs`): при тайм-ауте
  паника включает собранные строки stderr ребёнка (сейчас диагностика глухая),
  дедлайн 30 с → 60 с — запас на перегруженный раннер, на зелёном прогоне
  стоимость нулевая.
- Новый воркфлоу `.gitverse/workflows/ci.yml` — отдельный CI для GitVerse
  по его документированным возможностям: одна ubuntu-джоба, fmt + офлайн-тесты,
  `timeout-minutes: 15`, без clippy (удваивает сборку зависимостей; полный
  набор ворот остаётся на GitHub), без кэша, windows и недокументированных
  ключей (`permissions`, `concurrency`).
- Пользователь переключает в веб-морде GitVerse «приоритет для пути для
  конфигурационных файлов workflow» на `.gitverse/workflows` — после этого
  GitVerse перестаёт читать `.github/workflows` (пропадают вечное waiting
  windows-джобы и срабатывание `release.yml` на тегах GitVerse).

## Capabilities

### New Capabilities

Нет: поведение продукта не меняется — правки тестов и CI-конфигурация.
`skip_specs: true`.

### Modified Capabilities

Нет.

## Impact

- `src/pipeline.rs` — один тест (детерминизм относительно планировщика).
- `tests/cli_mock.rs` — один тест (диагностика + дедлайн).
- `.gitverse/workflows/ci.yml` — новый файл; `.github/workflows/ci.yml`
  не меняется (GitHub-ворота прежние).
- Веб-настройки репозитория на GitVerse — вручную пользователем.
- Возможное зеркалирование Pages-воркфлоу на ветке gh-pages, если он лежит
  в `.github/workflows` (проверяется в задачах).
