# Design

## Context

Конвейер обложек целиком в `src/cover.rs`: сервисы — варианты `enum Service` с пятью match-методами (`search_url`, `extract_cover`, `upgrade`, `image_host_suffixes`, `trusts_image_url`), порядок — `const CHAIN`, перебор — `search_cover`, транспорт — `trait CoverHttp` (`get_text` дефолтно декодирует `get_bytes`; продакшн `UreqCovers`, тестовый `FakeHttp`). Кеш ключуется `sha256("artist|title")`. Токенов и заголовков кроме `User-Agent: sevfm/<версия>` транспорт не знает. Мотивация — proposal.md, требования — дельта `album-art`.

Живые проверки 2026-11-11 (с сети пользователя): `api.discogs.com/database/search?q=…&type=release` ищет кириллицу (48 релизов на «Кобзон Катюша», первый — СССР/Мелодия), `cover_image`/`thumb` в ответе поиска пустые, картинки релизов — подписанные URL на `i.discogs.com`; анонимный доступ работает (заголовки `x-discogs-ratelimit: 25`).

## Goals / Non-Goals

**Goals:**
- Аутентичная обложка для советских песен — Discogs первым в цепочке.
- Токен по выбору пользователя, без встраивания секретов в поставку.
- Дисциплина сети без исключений для нового сервиса: лимиты, https-only, без редиректов, allowlist CDN.

**Non-Goals:**
- MusicBrainz+CAA: API поиска недоступен из сети пользователя (TLS-обрыв на обоих стеках), арт в CAA по советским релизам не найден — не включён.
- Отбраковка кандидатов по треклисту релиза (обложка сборки с нужной песней считается подходящей).
- Локальный троттлинг запросов Discogs и конфиг-файл приложения.

## Decisions

### D1. Discogs первым в CHAIN
`CHAIN = [Discogs, Itunes, Deezer, Yandex]`: цепочка останавливается на первом успехе, а жалоба пользователя — «ошибается», не «не находит»; после существующих сервисов Discogs чинил бы только полные промахи. Решение пользователя (2026-11-11). Цена — два запроса до остальных сервисов на современной музыке (~0.5–1 с при лимитах тела; кеш делает цену разовой на трек).

Альтернатива: последним — сохраняет латентность, не чинит неверный матч.

### D2. Двухшаговый поиск внутри сервиса, единая точка входа `resolve`
Схема Discogs: `q=<artist> <title>&type=release&per_page=5` → `results[0]` (пустой список — `Ok(None)`) → `GET api.discogs.com/releases/{id}` → первый элемент `images[]` с `type == "primary"` и непустым `uri` → поле `uri`. Второй шаг обязателен: в ответе поиска обложка пустая. Чтобы не ломать форму `extract_cover` (один проход по JSON), перебор в `search_cover` идёт через новый метод `Service::resolve(http, artist, title, token)`: дефолтная реализация — `search_url` + `get_text` + `extract_cover` (трое существующих без изменений), Discogs переопределяет двумя запросами. URL релиза — из недоверенного ответа поиска, и к запросу прицепляется токен: перед вторым шагом хост проверяется на https + сегментное совпадение с `api.discogs.com` (общий хелпер `trusted_host` с allowlist картинок), чужой хост — промах сервиса без запроса (находка security/hunter-ревью 2026-11-12). Отсутствие `primary` у релиза — промах сервиса; кандидаты 2–5 не пробуются (не умножать запросы против D6).

Параметрический поиск `artist=…&release_title=…` не используется: с кириллицей даёт 0 результатов (живая проверка).

Альтернативы: расширить `extract_cover` сигналом «нужен второй запрос» (скрытая машина состояний); спец-ветка в `search_cover` (два маршрута перебора в одном цикле); доверять `resource_url` без проверки хоста (канал утечки токена на произвольный https-хост при скомпрометированном ответе).

### D3. Авторизация как параметр транспорта
`CoverHttp::get_bytes`/`get_text` получают параметр `auth: Option<&str>` — готовое значение заголовка Authorization; его составляет сервис (`Service::auth_header`: только Discogs даёт `Discogs token=…`, остальные — `None`), `UreqCovers` при `Some` прикрепляет заголовок, `FakeHttp` пишет факт в журнал вызовов (для тестов токена). `None` — у всех запросов картинок (подписанные URL `i.discogs.com` самодостаточны). Сигнатура меняется в двух имплементациях и паре мест вызова — поверхность маленькая, взамен единый примитив без «молчаливых» потерь заголовка. Транспорт не знает о Discogs — механизм и политика разделены (уточнено по реализации, находка oracle-ревью).

Альтернативы: отдельный метод `get_text_authed` с дефолтной реализацией без заголовка (ловушка для будущих транспортов); второй транспорт для Discogs (дублирование агента с таймаутами).

### D4. Токен — переменная окружения, чтение при старте воркера
`SEVFM_DISCOGS_TOKEN`: непустая — токен, отсутствует или пуста — анонимно. Читается один раз при построении воркера (`Covers::start()` — продакшн; `with_backend` — тесты передают токен явно, нормализуя пустую строку в `None` единым фильтром), дальше хранится в состоянии потока и передаётся в `resolve`. Лог — только факт («Discogs: с токеном пользователя» / анонимно), значение не логируется. Конфиг-файл не вводится: подсистемы конфигурации в приложении нет, CLI минимален; переменная окружения работает на Linux и Windows без новой поверхности запуска.

Альтернативы: конфиг-файл (новая подсистема ради одного параметра); вшитый consumer key/secret (секрет в open-source поставке deb+zip утечёт).

### D5. Allowlist и апгрейд размера
`image_host_suffixes: Discogs => ["i.discogs.com"]`, `trusts_image_url` без изменений (суффикс-матч, https). Апгрейд `upgrade(url)` — тождество: размер зашит в подписанном Imgix-URL, клиентская замена параметров подпись ломает; берётся `uri` (полный размер), не `uri150`. Фактический размер полного `uri` подтверждён живым тестом 2026-11-12: 600×600 (Imgix `rs:fit h:600/w:600` — максимум записи «Кобзон Катюша»).

Альтернатива: параметризация Imgix-части URL (хрупко против подписей).

### D6. Rate limit не троттлим
Дискогсовский лимит 60/мин с токеном и 25/мин анонимно против ритма станции: смена трека каждые ~3 минуты плюс кеш по `artist|title` — в худшем случае порядка 10–15 запросов/час, запас больше десятикратного.

Альтернатива: локальный ограничитель частоты (новое состояние ради заведомо недостижимого потолка).

### D7. Диагностика отзыва анонимного доступа
Сбой Discogs — уже описанная ветка «недоступен». При HTTP 401/403 от API Discogs без токена лог дополняется подсказкой «задайте SEVFM_DISCOGS_TOKEN» — к моменту отключения анонимного доступа диагностика самодостаточна. Детекция — по HTTP-статусу в сообщении об ошибке (`HTTP 401`/`HTTP 403`) и отсутствию нормализованного токена, без разбора тела; пустой токен к этому моменту уже нормализован в `None` (`with_backend`, D4).

## Risks / Trade-offs

- [Discogs отключит анонимный доступ] → сбой первого сервиса, цепочка продолжает с iTunes; пользователь задаёт токен (D7); поведение соответствует сценарию дельты.
- [Первый кандидат `q=` — сборка, не точный релиз] → обложка сборки с нужной песней вместо ремейка постороннего исполнителя — улучшение по постановке задачи; треклист-фильтр не делаем (Non-Goals).
- [Обложки винилов — сканы среднего разрешения] → берём `uri` полного размера (D5); низкое разрешение лучше неверного изображения.
- [Два запроса на каждом промахе кеша] → +0.5–1 с к поиску современной музыки; кеш делает цену разовой на пару «исполнитель|название».
- [Rate limit при анонимном доступе ниже] → 25/мин против ~15/час худшего случая (D6).

## Migration Plan

Без схемы и хранимых данных: развёртывание — обычная поставка, токен опционален. Откат — удалить вариант `Discogs` из `Service`/`CHAIN` и вернуть сигнатуры `CoverHttp` (коммит целиком).

## Open Questions

Нет: спорные вопросы закрыты живыми проверками 2026-11-11 и 2026-11-12; фактический размер полного `uri` картинки — 600×600, подтверждён живым тестом и зафиксирован в D5.
