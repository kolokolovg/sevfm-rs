# Proposal

## Why

Поиск обложек часто ошибается на советских песнях: цепочка iTunes → Deezer → Яндекс либо возвращает современные ремейки («Катюша» в исполнении посторонних артистов), либо промахивается. Дискография лейбла «Мелодия» в этих каталогах фрагментарна (лицензионные ограничения), тогда как Discogs — пользовательский каталог винила — содержит аутентичные релизы СССР с обложками: живая проверка «Кобзон Катюша» вернула 48 релизов, первый — СССР / Мелодия / Д-0007609.

## What Changes

- Новый источник обложек Discogs в начале цепочки: Discogs → iTunes → Deezer → Яндекс.Музыка.
- Схема из двух запросов: `q=`-поиск по релизам (параметрический поиск с кириллицей даёт 0 результатов), затем `/releases/{id}` с выбором первой картинки типа `primary` с CDN `i.discogs.com`; URL релиза из недоверенного ответа перед догрузкой проверяется на родной API-хост — токен не покидает `api.discogs.com`.
- Необязательный токен пользователя из переменной окружения `SEVFM_DISCOGS_TOKEN`: без токена — анонимный доступ (работает сейчас, 25 запросов/мин; Discogs объявил его отключение — с токеном 60 запросов/мин). Секрет в бинарник не встраивается.
- Транспорт поиска получает поддержку авторизационного заголовка `Authorization: Discogs token=…` (картинкам он не нужен — подписанные Imgix-URL самодостаточны).
- Отказ Discogs (включая отклонение анонимного доступа) трактуется как сбой сервиса: цепочка переходит к iTunes, воспроизведение не затрагивается.

## Impact

- `src/cover.rs`: вариант `Service::Discogs` + ветки в match-методах, расширение `CHAIN`, двухшаговый поиск, авторизация в `CoverHttp` и `UreqCovers`/`FakeHttp`; allowlist дополняется `i.discogs.com`.
- Зависимостей нет (тот же `ureq`); новые сетевые хосты: `api.discogs.com` (поиск) и `i.discogs.com` (картинки).
