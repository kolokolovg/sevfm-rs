# Tasks

## 1. Модуль `src/icy.rs` — парсер и кадрировщик (чистые функции)

- [x] 1.1 `IcyFramer` по design D2: конечный автомат `Audio/размер-байт/Meta`, `push(&[u8]) -> аудиоучастки + завершённые метаблоки`; буфер неполного блока ≤ `1 + 255*16` байтов — одна аллокация на соединение; `metaint == None` — тождественный проход. Табличные юнит-тесты: блок целиком в чанке, блок на границе чанков, блок с размер-байтом 0, обрыв посреди блока. Верификация: `cargo test --lib icy`.
- [x] 1.2 `parse_meta` по design D3: байтовый поиск `StreamTitle='…'` (экранирование `''`), `from_utf8_lossy`, `serde_json` в `{artist, name, type}`; правила: JSON с непустым `artist` и `type == "М"` → трек с исполнителем; пустой `artist` или `type ≠ "М"` → вставка (только название); провал JSON → сырая строка как название; без `StreamTitle`/без `name` → `None`. Табличные юнит-тесты на реальных байтах станции: JSON `{"artist":"ВЛАДИМИР ТРОШИН","name":"ЮНОСТЬ МОЯ"}`, `'Реклама'`, обрезанный JSON, вставка `{"artist":"","name":"Говорит Севастополь","type":"Д"}`, мусорный блок. Верификация: `cargo test --lib icy`.
- [x] 1.3 `TrackInfo`/`NowPlaying` (design D5) + `proptest` (dev-зависимость, D6): инвариант фреймера `sum(audio) + sum(1+16*len) == вход`, аудио восстановлено точно при произвольных разрезах на чанки; `parse_meta` на произвольных байтах не паникует. Верификация: `cargo test --lib icy`.
