# Proposal

## Why

Фаза 1 сознательно не запрашивала ICY-метаданные (`Icy-MetaData: 1` не отправлялся) — плеер играет звук, но пользователь не видит, что в эфире. Продуктовая спека `radio-player` требует отделения метаданных от аудио и показа текущего трека; тракт фазы 1 стабилен и заархивирован — время закрыть этот срез.

## What Changes

- Reader-поток при подключении отправляет `Icy-MetaData: 1` и разбирает заголовки ответа `icy-metaint` (интервал блоков) и `icy-name` (название станции).
- Блоки ICY-метаданных **вырезаются из байтового потока до буфера**: декодер по-прежнему получает чистый MP3, тракт фазы 1 не меняется.
- Поле `StreamTitle` разбирается по правилам продуктовой спеки: JSON с `artist`/`name` — использовать их; иначе — строка как есть; обрезанный JSON — сырая строка без краха.
- Рекламные/новостные вставки распознаются (пустой `artist` или `type` ≠ «М») и показываются как название без исполнителя.
- CLI (фаза без UI) печатает название станции при подключении и смену трека в stderr через `say()`; отображение в окне — будущая фаза Slint.
- Устойчивость: обрезанный блок на границе чтения/обрыва, мусор в блоке, отсутствие icy-заголовков у сервера — воспроизведение не страдает, процесс не падает.

Не входит (Non-goals): обложки (iTunes/Deezer/Яндекс — требуют UI, отдельный change), окно Slint, ICYv2/Ogg-комментарии.

## Capabilities

### New Capabilities

- `icy-metadata`: запрос и отделение ICY-метаданных в сетевом тракте, разбор `StreamTitle` (JSON/строка/вставки), устойчивость к повреждённым метаданным, представление текущего трека и названия станции потребителю (CLI в этой фазе).

### Modified Capabilities

(нет — требования `radio-player` остаются продуктовым контрактом, `audio-pipeline` не меняется: декодер продолжает получать только аудиобайты)

## Impact

- `src/net.rs`: заголовки запроса/ответа, кадровка по `icy-metaint` в цикле чтения, вырезание блоков до `buffer.write`, повторная договорённость при переподключении.
- Новый модуль `src/icy.rs`: разбор метаблока и `StreamTitle` (чистая функция над байтами — свойственен property-based-тестам).
- `src/main.rs`: печать станции/трека в stderr по смене.
- Общая слот-структура «текущий трек» (по образцу `Link`/`NetStatus`).
- Зависимости: вероятен `serde_json` (разбор JSON в `StreamTitle`, без default-features) и dev-зависимость `proptest` (скилл требует PBT для парсера ICY-метаблоков) — точное решение фиксирует design.md.
- Тесты: юнит-таблицы и proptest для парсера; мок-сервер сценарии «аудио+метаданные» (чистота аудиопути, смена трека, переподключение, сервер без ICY).
