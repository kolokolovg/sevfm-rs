# Design

## Context

Окно сегодня — `PlayerWindow` в `ui/player-window.slint`: VerticalLayout-список (обложка-блок 210px, станция, статус, трек, ошибка, std-widgets кнопки), фон `#14161d`, свободный ресайз. Данные из Rust: `station`, `status` (лейбл), `artist`, `track-title`, `error`, `cover` (image, Rust уже кладёт заглушку при сбросе — правило видимости `TrackSlot` из `src/ui.rs`), `can-play`/`can-stop`, колбэки `play()`/`stop()`. Утверждённые мокапы пяти состояний — в визуализациях сессии (Играет / Реклама / Остановлено / Обрыв сети / Ошибка).

## Goals / Non-Goals

**Goals:**

- Слоистая композиция «Герой»: фон-обложка `cover`, градиент-затемнение снизу, центрированная колонка контента, стеклянные кнопки.
- Фиксированный кадр 440×560 без ресайза.
- Цвет индикатора состояния — производная `UiState` + видимой ошибки, без новых сетевых/аудио данных.

**Non-Goals:**

- Анимации (пульс точки, появление обложки), светлая тема, громкость/пауза — не входят.
- Смена модели данных `TrackSlot`/`PlayerView` и поведения гейтов кнопок.
- Трей и MPRIS (тултип и метаданные продолжат брать те же строки).

## Decisions

### D1. Фиксированный размер: `min = max = preferred`

`preferred-width/height: 440px/560px` остаются, добавляются `min-width: 440px; max-width: 440px; min-height: 560px; max-height: 560px`. Это декларативный механизм Slint без Rust-кода. Альтернатива — трюк с `no-frame` и кастомным тайтлбаром — отклонена: теряем нативную рамку KDE и close-to-tray поведение из add-tray. Риск: отдельные бэкенды игнорируют max-hints — закрывается живой проверкой (задача в tasks): растягивание мышью и двойной клик по тайтлбару (maximize).

### D2. Слои композиции вместо VerticalLayout-списка

Корень `PlayerWindow` — `Rectangle` с детьми по порядку (уточнение по ручной приёмке: вариант «Карточка» вместо полноэкранной заливки — cover резал бока квадратных обложек):

1. Подложка: тёмный фон окна `#0b0d13` (полноэкранный `Image`-фон убран).
2. Карточка обложки: `Rectangle` 350×350 по центру (центр на ~34% высоты), `border-radius: 16px`, `clip: true` — внутри `Image { source: root.cover; image-fit: cover }` (у `Image` нет `border-radius`, скругление даёт обрезка контейнера), мягкая тень `drop-shadow-*`. Заглушка-герб показывается той же карточкой; отдельное свойство не вводится — Rust уже кладёт заглушку в `cover` (D7 add-album-art).
3. `Rectangle` градиент: нижние ~60%, `background: @linear-gradient` от прозрачного к `#0b0d13` — читаемость текста на светлых обложках.
4. `VerticalLayout` контента (padding 26, spacing 12): верхний `Rectangle { vertical-stretch: 1 }`-спейсер прижимает блок к низу; все дети центрированы.

Альтернативы отклонены: полноэкранный `cover` (резал бока — находка ручной приёмки), `contain` на всю площадь (тёмные поля, «герой» теряется).

### D3. Индикатор состояния: enum `StatusKind`, красный — из `error`

В `.slint` объявляется `enum StatusKind { playing, waiting, stopped }`; Rust передаёт `in-out property <StatusKind> status-kind` вместо вывода цвета из строки лейбла. Маппинг `UiState → StatusKind` — новый метод в `src/ui.rs` (playing → `playing`; connecting/buffering/reconnecting → `waiting`; stopped → `stopped`), таблично тестируется в lib-тестах. Красный цвет точки в Slint вычисляется как `root.error != ""` — ошибка видима только в «Остановлено» и сбрасывается следующим «Играть», поэтому отдельный вид не нужен. Альтернативы отклонены: парсить строку статуса в Slint (хрупко), передавать готовый цвет из Rust (утечка визуала в логику).

### D4. Кнопки: свой компонент вместо std-widgets

`GlassButton` в `player-window.slint`: `Rectangle` (радиус 999px) + `TouchArea`, состояния по `has-hover`/`pressed`; два варианта — «стекло» (полупрозрачный `#ffffff1F`) и «strong» (белая заливка, тёмный текст), иконка + текст. Иконки — векторные примитивы Slint без ассетов: треугольник `Path` для «Играть», маленький `Rectangle` для «Стопа». Правило акцента: `strong` носит доступная кнопка (`enabled: root.can-play || коррелят`), disabled — полупрозрачен. Альтернатива `std-widgets.slint Button` отклонена: нативная кнопка не встаивается в композицию поверх обложки (своя палитра и геометрия). Уточнение по факту реализации: у `TouchArea` нет фокус-состояния (проверено компилятором), поэтому focus-кольца и клавиатурной активации (Tab/Enter) у кнопок нет — см. риски.

### D5. Трек-строка — три формы `TrackSlot`, станция уходит из окна

Главная строка рендерится по текущим полям без смены протокола: `artist != ""` → артист капсом мелко + название крупно; иначе `track-title != ""` → одна строка крупно; иначе (`station`, может быть пустой) → строка-станция. Отдельный `Text` станции удаляется: название остаётся в `title` окна и в заглушке трек-строки. Биндинги `set_station`/`set_artist`/`set_track_title` в `main.rs` сохраняются — Slint сам различает формы.

### D6. Плашка ошибки

`if root.error != "":` стеклянный красный `Rectangle` (радиус 10, полупрозрачный `#d6365 0`-тон) с текстом 13px над кнопками; правило жизни «до следующего Играть» не меняется (сброс в `command_play` уже есть).

## Risks / Trade-offs

- [Бэкенд игнорирует min/max-hints окна] → живая проверка ресайза и maximize на KDE Wayland в задачах; при отказе — фиксация через backend API Slint как отдельная маленькая задача с ревью. По исходникам winit/Wayland это хинты `xdg_toplevel.set_min/max_size` (протокольный уровень, ревью oracle); остаточный случай — тайловые WM (i3/sway в тайлинге) игнорируют size-hints и растягивают окно: деградация мягкая, композиция центруется при любом размере — принято.
- [Светлые/пёстрые обложки съедают контраст текста] → градиент D2.2 затемняет до `#0b0d13` у нижнего края, где весь текст; проверяется живьём на светлой обложке.
- [Обложка-«скриншот» нестандартных пропорций] → `ImageFit.cover` центрует и режет края; крайний случай (сильно вытянутая) деградирует мягко — допускаем.
- [Кастомные кнопки теряют нативный фокус/клавиатуру std-widgets] → принято осознанно: у `TouchArea` нет фокус-состояния, клавиатурная активация (Tab/Enter) в фазе отсутствует — управлением мышью/треем/MPRIS сценарии закрываются; клавиатурные шорткаты спека player-ui не требует. Если понадобятся — отдельный мини-change с FocusScope; туда же добавить `accessible-role`/`accessible-label` кнопкам — сейчас экранный диктор их не видит (ревью oracle).
