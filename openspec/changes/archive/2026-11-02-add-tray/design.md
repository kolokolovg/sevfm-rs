# Design

## Context

UI-режим — Slint-окно плюс `slint::Timer` на 100 мс, тикающий `SessionHandle::tick()` (станция, трек, `NetStatus`, underrun); команды — замыкания `on_play`/`on_stop` в `src/main.rs`; headless-режим — собственный цикл без окна. Закрытие окна сегодня гарантированно завершает процесс (`main.rs:443–470`). Код синхронный, без async-runtime. Мотивация — в `proposal.md` (Why).

Ключевая находка планирования: у Slint 1.18 есть встроенное API `SystemTrayIcon` (feature `system-tray`, входит в дефолтные): tray-компонент объявляется прямо в `.slint`, меню декларативно, бэкенды — `ksni` 0.3 на Linux (уже компилируется в дереве проекта как зависимость slint), `Shell_NotifyIconW` на Windows, AppKit на macOS. Выбор стека зафиксирован пользователем после сравнения с прямыми крейтами ksni/trayicon (2026-11-02).

## Goals / Non-Goals

**Goals:**
- Трей через встроенное `SystemTrayIcon` на Linux и Windows: ноль новых зависимостей для трея, ноль платформенного кода от нас.
- MPRIS-сервис на Linux — mpris-server 0.11 в выделенном `std::thread`, без tokio/async-std.
- Close-to-tray с сохранением всех гарантий полного выхода (стоп, сеть, код 0, без зависающих потоков).
- Деградация без среды: нет трея/D-Bus — приложение работает в прежнем оконном режиме.

**Non-Goals:**
- Любые медиа-интеграции на Windows (SMTC и аналоги) — вне запроса пользователя.
- Пауза, перемотка, плейлисты, статус-иконки трея, balloon-уведомления.
- Трей и MPRIS в headless-режиме.
- Рантайм-тестирование на Windows: кросс-проверка сборкой, ручной запуск — вне рамок.

## Decisions

### D1. Трей — встроенный `SystemTrayIcon` Slint 1.18
Трей — отдельный экспортируемый tray-компонент в `ui/player-window.slint` (`inherits SystemTrayIcon`, обязан быть корнем компонента): свойства `icon` (через `@image-url` — компилятор Slint сам встраивает и декодирует PNG), `tooltip`, `visible`; меню — декларативное `Menu { MenuItem { title, enabled, activated } }`, авто-перестройка при смене свойств (ChangeTracker внутри item) — динамическая доступность «Играть»/«Стоп» и label «Показать/Скрыть окно» — просто свойства. ЛКМ — callback `clicked`. Бэкенды: ksni 0.3 (Linux, события доставляются dispatcher-задачей в event loop Slint), Shell_NotifyIconW в winit-насосе (Windows, TaskbarCreated обработан), AppKit (macOS). Rust-сторона: `PlayerTray::new()`, `show()/hide()` (видимость значка), set-теры свойств, `on_clicked`/`on_*` колбэки; событие кликов приходит в event loop — мост не нужен.
Альтернативы: прямые крейты ksni + trayicon (исходный план; ~200–300 строк нашей платформенной обвязки и интеграция message-pump со Slint на Windows — отвергнуто пользователем после сравнения); гибрид «встроенное + trayicon на Windows» (два механизма — отвергнуто).

### D2. Общие хендлеры команд; `invoke_from_event_loop` — только для MPRIS
Общие хендлеры play/stop/show-window/hide-window/quit выделяются из `on_play`/`on_stop` и переиспользуются всеми тремя источниками: кнопки окна, пункты меню трея и ЛКМ (колбэки .slint, уже в event loop), MPRIS (D-Bus-поток — команды через `slint::invoke_from_event_loop`; паттерн «в цикл из любого потока» опробован ctrlc-обработчиком).
Данные (тултип, доступность пунктов) — push из существующего 100-мс тика: Slint-свойства дедуплицируются ChangeTracker'ами сами; отдельный diff-кеш трею не нужен.

### D3. Жизненный цикл трея и деградация
`PlayerTray::new()` в `run_ui` до запуска цикла (главный поток). Среду пробуем до создания (находка ревью oracle): шины мало — нужен SNI-хост, `NameHasOwner("org.kde.StatusNotifierWatcher")` через `zbus::block_on` (zbus из дерева mpris-server); проба даёт раннюю диагностику с причиной в логе, ошибки `new()` — вторая линия. Проба идёт в отдельном потоке с таймаутом 3 с (находка ревью hunter: у zbus нет таймаута handshake, «чёрная дыра» в адресе шины не должна вешать старт UI). Отказ ⇒ трей не создаётся, close-to-tray выключен — закрытие окна завершает процесс как сегодня (спека system-tray «Деградация» покрывается, включая GNOME без расширения). Трейд-офф: автозапуск раньше панели получает отказ на всю сессию — принято. Компонент живёт до конца `run_ui`. MPRIS отказывает независимо от трея.
Подтверждено исходниками slint 1.18: `run_event_loop_until_quit` = `set_event_loop_quit_on_last_window_closed(false)` + цикл (lib.rs:265); `on_close_requested` возвращает `CloseRequestResponse::HideWindow` — окно скрывается, цикл не завершается (api.rs:458–530); `Weak<T>: Send` (api.rs:1247); `WindowItem.icon` (items.rs:1274).

### D4. mpris-server: готовый `Player` в выделенном потоке + `zbus::block_on`
Крейт async-only, zbus 6 не имеет blocking-API: поток `std::thread` с `zbus::block_on`. Используется готовая структура `mpris_server::Player` (не трейт): `Player::builder("sevfm")` c флагами, `connect_*` для команд, async-сеттеры `set_playback_status`/`set_metadata`, сами дедуплицирующие повторные значения и шлющие PropertiesChanged, и `run()` — future обработки вызовов. `Player` на `Rc`: весь живёт в mpris-потоке; наружу — `async_channel`-отправитель обновлений (Send) и колбэки команд через D2. Гонка `run()` и обновлений — рукописный мини-селект из двух futures (зависимость futures не нужна; async-channel уже в дереве zbus).
Bus name `org.mpris.MediaPlayer2.sevfm`, Identity «Говорит Севастополь». `mpris:artUrl` — `file://` на файл персистентного кеша обложек (публичный `cached_cover_path` в cover.rs); обложки нет — поле опускается. Ошибка шины ⇒ поток логирует и завершается, на остальное не влияет.
Находки ручного тестирования виджета KDE (исходник plasma-workspace `applets/mediacontroller`): кнопки «стоп» у виджета нет вообще, плей-пауза при играющем потоке вызывает метод `Pause` напрямую — поэтому `CanPause=true` и `Pause` работает как «Стоп» (иначе кнопка серая/нерабочая).
Альтернатива: tokio-рантайм ради одного потока — избыточно; `zbus::block_on` — минимальный подтверждённый путь.

### D5. Close-to-tray: `run_event_loop_until_quit` + `on_close_requested`
Переход с `window.run()` на `slint::run_event_loop_until_quit()`: цикл живёт до явного `quit_event_loop()`. `on_close_requested`: трей жив ⇒ только `HideWindow` (окно скрывается, воспроизведение и процесс живут); трея нет ⇒ `quit_event_loop()` + `HideWindow`. Полный выход («Выход» из трея, SIGINT/SIGTERM, MPRIS Quit) ⇒ `quit_event_loop()`, существующий teardown после цикла (стоп, join со сторожем, `exit(0)`) выполняется без изменений. Сигнальный обработчик уже зовёт `quit_event_loop`; повтор по флагу из первого тика сохраняется.

### D6. Ассет иконки — один PNG из герба Севастополя
`ui/app-icon.png` (256×256 RGBA) — герб Севастополя, вырезанный по альфа-bbox из заглушки обложки `ui/cover-placeholder.png` (запрос пользователя). Одна картинка на оба применения: значок трея (`icon:` в tray-компоненте) и иконка окна в заголовке/таскбаре (`Window.icon`, `items.rs:1274`). Подключение — `@image-url` в `.slint`: компилятор встраивает и декодирует сам, бэкенды конвертируют сами (ksni — ARGB32, Windows — HICON). Rust-декода и `.ico`-версии нет. Мелкие детали монумента на 16 px могут замылиться — принято (SNI-хосты масштабируют от 32).

## Risks / Trade-offs

- [Молодость API `SystemTrayIcon` (новое в 1.18)] → бэкенды прочитаны по исходникам (ksni-обёртка с dispatcher-задачей и respawn при visible-toggle; Windows с TaskbarCreated и message-only окном в winit-насосе); изоляция — tray-компонент локализован в .slint и wiring в run_ui, при баге замена на прямые крейты не трогает остальное.
- [Два мажора zbus в дереве: 5 (через ksni/slint) и 6 (через mpris-server)] → изоляция MPRIS в одном модуле, контроль `cargo tree -d`; дублирование принято.
- [ksni в среде без SNI-хоста (GNOME без расширения)] → закрывается пробой `NameHasOwner` наблюдателя при старте (находка ревью oracle, D3); остаточный риск — наблюдатель появляется позже старта приложения — принят (трей не создаётся на сессию, лог сообщает причину).
- [Смерть шины D-Bus в рантайме после успешного старта] (находка ревью hunter) → ksni service-поток умирает молча, значок исчезает, но `tray_alive` уже взведён — закрытие окна спрячет его без значка; спасает SIGINT. Сценарий практически катакстрофичен для сессии (смерть dbus-daemon рушит пользовательскую сессию) — остаточный риск принят осознанно.
- [Снятие имён D-Bus при выходе] (находка ревью hunter) → ни zbus, ни mpris-server не шлют ReleaseName в Drop, ksni `shutdown()` без wait: снятие имён и значка держится на гарантированной очистке демоном при закрытии сокета — семантика D-Bus; исчезновение имени проверено живым тестом.
- [Асинхронность mpris-server в sync-коде] → весь async заперт в одном потоке D4, наружу — только команды и эмитеры.
- [Рассинхрон тултипа/меню при ручном set] → единственная точка push — тик; свойства с одинаковым значением не дёргают ChangeTracker.

## Migration Plan

Порядок внедрения: D2 (общие хендлеры) → D5 (until_quit + close) → D1 (.slint tray-компонент + wiring) → D6 (ассет) → D4 (MPRIS) → гейты сборки и тестов. Каждый этап оставляет приложение работоспособным. Откат: трей и MPRIS отключаются независимо (не создавать компонент/поток); полный откат — revert change.

## Open Questions

- Точный формат `ksni::Icon::Data` больше не актуален (конвертацию делает slint); сверка не нужна.

## Отложено пользователем (2026-11-02)

- `.desktop`-файл для иконки приложения в таскбаре/заголовке окна на Wayland: KWin берёт иконку не из `Window.icon` (протокол Wayland её не передаёт), а из desktop-файла по app_id. Пользователь решил отложить отдельным change; в этом change на Wayland в таскбаре/заголовке стандартная заглушка (в окне, трее и MPRIS герб есть), `Window.icon` работает для X11/Windows.
