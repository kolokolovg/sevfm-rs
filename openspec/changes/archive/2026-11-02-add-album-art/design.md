# Design

## Context

После фазы add-player-ui окно показывает статичный квадрат-заглушку (`ui/player-window.slint`), `PlayerView` в `src/ui.rs` отдаёт смены `TrackSlot` (Track/Title/Placeholder) с дедупликацией, poll-таймер `src/main.rs` пишет их в окно. HTTP уже в lib (`ureq`, `net.rs`), JSON — `serde_json`.

Из Java-версии (по указанию пользователя) взята только схема получения обложек и ссылки: цепочка сервисов, формат поискового запроса, ключи в ответах и апгрейд размеров картинок. Всё остальное — кеш, потоковая модель, константы, подключение к окну — спроектировано под sevfm-rs без паритета с Java.

## Goals / Non-Goals

**Goals:**

- Цепочка iTunes → Deezer → Яндекс.Музыка: первый непустой результат побеждает, сбой сервиса не прерывает цепочку и воспроизведение.
- Дисковый кеш повторных треков, переживает перезапуск, без сети на повторе.
- Асинхронность: тракт и окно не ждут сеть; устаревший ответ не применяется.
- Отображение обложки в Slint по правилу видимости трек-строки.

**Non-Goals:**

- Синхронизация обложки с аудио-долотом (метаблоки в очереди) — отдельный change эфира.
- Отрицательный кеш (повторный промах снова ходит в сеть).
- Ограничение размера кеша, чистка, PNG/WebP.
- Предзагрузка следующих треков, выбор размера пользователем.

## Decisions

### D1. Схема поиска: эндпоинты, запрос, апгрейд размеров

Таблица — зафиксированная схема (взятое из референса):

| Сервис | Поиск | Ключ в JSON | Апгрейд |
|---|---|---|---|
| iTunes | `https://itunes.apple.com/search?term=<enc>&entity=song&limit=5` | `artworkUrl100` | `100x100bb` → `600x600bb` |
| Deezer | `https://api.deezer.com/search?q=<enc>&limit=5` | `cover_big` | `/500x500-` → `/1000x1000-` |
| Яндекс | `https://api.music.yandex.net/search?text=<enc>&type=track&page=0` | `coverUri` | префикс `https://`, `%%` → `1000x1000` |

Поисковая строка — `artist + " " + title`; пробел кодируется `+` у iTunes и `%20` у Deezer/Яндекса (эти сервисы надёжнее понимают `%20`). `page=0` у Яндекса обязателен — без него HTTP 400. Модуль `src/cover.rs`: enum `Service` и одна функция поиска с матчем по сервису — цепочка фиксирована, иерархия trait-провайдеров не нужна.

Все три сервиса возвращают списки кандидатов, а не один трек: берётся первый элемент списка с непустым ключом обложки — верх ранжирования сервиса. Поиск написания не сверяет: при отсутствии точного трека в каталоге могут вернуться одноимённые (каверы, компиляции) — верх чужого ранжирования станет обложкой и кеш её зафиксирует; сверка кандидата с запросом — вне scope этого change. У Яндекса поиск нестрогий (fuzzy): находит при отличиях в написании и отдаёт широкий список, поэтому он третий эшелон. Живой квирк Deezer (2026-11-02): часть русскоязычного каталога скрыта гео-фильтром — `total` ненулевой при пустых `data`.

### D2. Разбор ответов — `serde_json`

Крейт уже есть; ручной сканер подстрок повторял бы баг-поверхность библиотеки (прецедент фазы ICY). iTunes — массив `results[]`, Deezer — `data[]`, Яндекс — `result.tracks.results[]` (схема живого API на 2026-11-02; прежний `tracks.items` исчез — Java-сканер подстрок пережил смену незаметно, строгий путь поймал её живым тестом); из элементов берётся первый непустой URL-ключ. Пустой или отсутствующий массив — промах (`None`, следующий сервис); сетевая/HTTP-ошибка — `Err`, запись в лог и следующий сервис.

### D3. Транспорт: отдельный `ureq::Agent`, инъекция для тестов

Свой агент с таймаутами соединения, заголовков и каждого чтения по 5 с, общий бюджет тела 15 с (пер-чтение не ограничивает медленный trickle-CDN — находка ревью) и `User-Agent: sevfm/0.1` — у радио-агента в `net.rs` другие настройки, их не трогаем. Тонкая прослойка-трейт (`get_text`, `get_bytes`) существует только для fake-транспорта в юнит-тестах без сети; продакшн-реализация — обёртка агента, не-2xx — ошибка. Декод картинки — с лимитами 4096×4096: чужой JPEG с гигантской декларацией размеров не аллоцирует сотни мегабайтов.

### D4. Кеш: каталог XDG, ключ-хеш, валидация декодом

Каталог `<XDG_CACHE_HOME|~/.cache>/sevfm/covers/`, файл — `<sha256("artist|title")>.jpg` (крейт `sha2`): имя файлобезопасно, без коллизий и без лимита длины. Запись — во временный файл с `fs::rename` в тот же каталог (атомарно, обрыв не оставляет половину). Валидация содержимого — не сниффинг магии, а декод: скачанные байты сразу декодируются (`image`), не декодируются — не кешируем, заглушка. Попадание — байты из файла → декод; битый файл удаляется и считается промахом (поиск повторится).

### D5. Воркер-поток с каналом, последний запрос выигрывает

Поток `cover-service` + `std::sync::mpsc`: воркер дренирует канал до самого свежего запроса (смена треков быстрее ответов не копит очередь). Каждый запрос нумеруется генерацией; воркер шлёт ответ с генерацией запроса, а гасятся устаревшие при дренировании на стороне потребителя (`poll_reply`) — все bump'ы генерации и дренирование идут из одного потока потребителя, поэтому сверка там атомарна и закрывает ответы, уже лежащие в канале (TOCTOU «проверил-и-отправил» в воркере неустраним — находка ревью). Блокирующий HTTP не прерывается посреди чтения — верхняя граница занятости определяется таймаутами D3. Поток не джойним при выходе: гарантия «код 0 ≤ 1 с» не зависит от сети сервисов обложек.

### D6. Подключение к окну и headless

Источник запросов — poll-таймер по смене `update.track`: слот `Track` запускает поиск (artist/title уже в слоте), `Title` и `Placeholder` — заглушка немедленно, без обращения к сервисам (спека album-art). `PlayerView` не меняется. Ответы забирает тот же poll-таймер опросом канала (`poll_reply`, 100 мс): окно пишет один поток, `invoke_from_event_loop` не нужен; до готовности остаётся прежняя обложка, вставка и остановка дают заглушку (спека player-ui). Headless: тот же сервис, результат и источники поиска пишутся в лог через `say`.

### D7. Заглушка — дефолт свойства окна; декод в lib, сборка `Image` в bin

`ui/player-window.slint`: `in-out property <image> cover: @image-url("cover-placeholder.png")` — заглушка встроена в разметку, PNG кладём рядом с разметкой. Rust читает её один раз при старте (`window.get_cover()` до первого `set`) и использует как значение сброса — отдельное свойство-флаг «это заглушка» не нужно. Найденная обложка: JPEG-байты → `image` (`default-features = false`, только `jpeg`) → RGB8-буфер. Декод — чистая функция в lib (тестируется без окна), сборка `SharedPixelBuffer` и `slint::Image::from_rgb8` — в bin, lib от Slint не зависит.

## Risks / Trade-offs

- [Яндекс-эндпоинт неофициальный, схема ответа может измениться] → изоляция в одной ветке матча D2; деградация до заглушки, не крах; сбои видны в логе (смена схемы уже случалась — `tracks.items` → `result.tracks.results`, поймано живым тестом).
- [Первый кандидат без сверки исполнителя: одноимённые треки дают чужую обложку, кеш её фиксирует] → осознанный trade-off D1; сверка кандидата — потенциальный будущий change.
- [Кеш растёт неограниченно] → осознанный trade-off этого change; лимит и чистка — вне scope (осиротевшие `.tmp` подчищает старт воркера).
- [Смена треков быстрее ответов сервисов] → дренаж канала + генерация D5: устаревшие ответы гасятся вплоть до дренирования, занят один запрос.
- [`get_cover()` как источник заглушки зависит от дефолта разметки] → читается ровно один раз до любых `set_cover`; проверяется headless-сборкой разметки.

## Migration Plan

Миграции нет: новый модуль и свойство окна, существующее поведение не меняется. Откат — удалить `cover.rs`, свойство `cover` и подключение в `main.rs`; кеш-каталог можно удалить вручную.
