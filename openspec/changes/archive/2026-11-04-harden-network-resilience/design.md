# Design

## Context

Два HTTP-контура приложения настроены по-разному. Стрим-агент (`src/net.rs:164-184`) закрывает все фазы таймаутами, запрещает редиректы и читает поток порциями; агент обложек (`src/cover.rs:183-190`) имеет таймауты connect/response/read/body, но без `timeout_resolve`, с дефолтными редиректами ureq (до 10), без требования https, а тело читается `read_to_end` без ограничения (`src/cover.rs:213-218`). При этом URL картинки приходит из недоверенного ответа поиска. Классификация статусов стрима (`src/net.rs:603-616`) считает перманентным весь диапазон 3xx–4xx, включая повторяемые 408/429. `parse_args` (`src/ui.rs:242-264`) не проверяет URL, и битый адрес ретраится вечно. Паника воркера обложек (`src/cover.rs:477,540-564`) не ловится: обложки исчезают молча.

## Goals / Non-Goals

**Goals:**
- Привести контур обложек к транспортной дисциплине стрим-контура: ограниченное тело, без редиректов, только https, только доверенные CDN, резолв с таймаутом.
- Сделать аварию воркера обложек наблюдаемой (одна запись в лог, деградация без сети).
- 408/429 стрима перевести в повторяемые отказы; битый URL — в мгновенный отказ запуска.

**Non-Goals:**
- Восстановление (respawn) воркера обложек после паники — паника может быть систематической, перезапуск даст петлю.
- Eviction дискового кеша обложек, контрольные суммы релизов, SHA-пины CI-экшенов (другие пункты обзора).
- Проверка достижимости/типа контента URL при старте — валидация синтаксическая.
- Изменение поведения стрим-агента (редиректы/https уже закрыты там).

## Decisions

### D1: Лимит тела ответа обложек — чтение через `take` с параметром лимита
Лимиты — константы: поисковый JSON 1 МиБ (`SEARCH_BODY_LIMIT`), картинка 10 МиБ (`IMAGE_BODY_LIMIT`). Чтение: `into_reader().take(limit + 1)` + `read_to_end`; если прочитано больше лимита — `CoverError::BadResponse("превышен лимит тела …")` (находка ревью: огромный ответ — вина ответа, не сети — ветка «вернул мусор», а не «недоступен»), лишние байты не читаются. Запас против живых ответов ~×100: поиск с `limit=5` — единицы–десятки КиБ (живой замер 2026-11-02), `cover_big`/`1000x1000` — сотни КиБ. Трейт `CoverHttp::get_bytes` получает параметр лимита (поиск/картинка), fake-транспорт тестов проходит тот же путь.
*Альтернатива*: `ureq::Body::builder().limit()` — завязывает ограничение на конкретный транспорт, тесты fake-транспорта его не проходят. Отвергнуто.

### D2: Агент обложек — `max_redirects(0)`, `https_only(true)`, `timeout_resolve(5 с)`
Симметрия со стрим-агентом (`net.rs:178-181`): резолв ограничен (зависший DNS больше не блокирует единственного воркера), редиректы запрещены (ответ поиска не может увести загрузку на произвольный хост), не-https URL отклоняются транспортом.
*Риск*: сервис, начавший отдавать http-ссылки, деградирует в промах — осознанный отказ от нешифрованного трафика.

### D3: Allowlist CDN-хостов по сервису цепочки
Перед загрузкой картинки хост URL сверяется с суффиксами сервиса, вернувшего URL: iTunes — `.mzstatic.com`, Deezer — `.dzcdn.net`, Яндекс — `avatars.yandex.net`. Сравнение сегментное (`host == suffix || host.ends_with(".{suffix}")`-эквивалент) без учёта регистра и хвостовой FQDN-точки — семантика DNS (находка ревью): `evil-dzcdn.net` не проходит, честный ответ в верхнем регистре не теряется. Чужой хост — промах сервиса (не сетевой сбой): цепочка переходит к следующему, в логе хост и причина (`чужой хост …` / `хост … не по https`). Разбор authority — `http::Uri` (см. D5). Поисковые эндпоинты — собственные константы кода, allowlist'ом не проверяются (их покрывают D2).
*Альтернатива*: проверка на уровне агента — ureq не даёт per-host политики. Отвергнуто.

### D4: 408/429 — повторяемые, остальной 3xx/4xx — перманентный отказ
Условие фатальности в reader-цикле (`net.rs:603`): `Status(code)` фатален, когда `300..500` содержит код и код не 408/429. Повторяемые статусы идут общим transient-путём (`net.rs:617`) с существующей формулировкой `подключение не удалось: стрим недоступен: HTTP {code}`, отдельная не вводится. 5xx и сегодня повторяемы (вне диапазона), 3xx остаётся перманентным — редиректы стрима запрещены дизайном.

### D5: Валидация URL — `http::Uri` в `parse_args`
Новая прямая зависимость `http` (уже в дереве через ureq — тот же парсер, которым ureq разбирает URL запроса). В `parse_args` после сбора аргументов финальный URL (включая дефолтный `DEFAULT_STREAM_URL` — самопроверка константы) разбирается `Uri::from_str`: требуются схема `http`/`https` и непустой host. Ошибка — через существующий канал `Err(String)` → stderr и код 2 до открытия окна в обоих режимах (`main.rs:413-418`). То, что не парсится `Uri`, сегодня не подключится и ureq'ом — отказ лишь переносится с первой попытки соединения на старт.
*Альтернатива*: ручная проверка префиксов — пропускает `http://exa mple.com`; `url::Url` — тяжёлая новая зависимость. Отвергнуты.

### D6: Паника воркера обложек — `catch_unwind` + флаг «мёртв»
Тело `worker_loop` в спавне (`cover.rs:477`) оборачивается `catch_unwind(AssertUnwindSafe(...))` (прецедент: symphonia в `pipeline.rs:414,636`). Паника → запись `say("сервис обложек аварийно завершился: …")` + `Arc<AtomicBool>` в `Covers`; `request()` при поднятом флаге тихо пропускает запрос (без `send`), `poll_reply` и заглушка работают как раньше. Флаг поднимается и при отказе спавна потока — один контракт мёртвости (находка ревью). Публичный `Covers::is_dead()` даёт потребителю в UI поставить заглушку сразу, не ожидая ответа (спека album-art «Диагностика аварии воркера»; находка ревью P1). Отказ спавна и паника дают в stderr две записи (дефолтный panic-hook + say) — принято, как у симфонийного прецедента.
*Альтернатива*: respawn воркера — петля паник при систематическом баге; heartbeat — сложнее без выгоды. Отвергнуты.

## Risks / Trade-offs

- [Аномально большой честный ответ поиска превысит 1 МиБ] → деградация в промах сервиса, не крах; запас ×100 против замеренных ответов, значение — константа с обоснованием.
- [Смена CDN сервисом сломает allowlist] → в логе будет «чужой хост»; живой тест обложек (обёртка с блокировкой сервисов) заметит на следующем прогоне; правка — одна константа.
- [408/429 теперь ретраятся неограниченно] → тот же контракт, что у сетевых отказов: выход по сигналу/«Стоп», не крахом — соответствует спеке.
- [`http` как прямая зависимость] → минимальный crate, уже компилируется в дереве; версия следует за требованием ureq.

## Migration Plan

Чистая правка кода без миграции данных и форматов. Порядок: D1+D2+D3 (одна зона `cover.rs`), D6 (там же), D4 (`net.rs`), D5 (`ui.rs`, `Cargo.toml`). Откат — реверт коммита, взаимодействующих состояний нет.

## Поведение простыми словами

Обложки: воркер ходит в три каталога по https, не farther одного хоста за раз (без редиректов), картинку качает только с родного CDN сервиса и не больше 10 МиБ, поиск — не больше 1 МиБ; всё, что нарушает правила, считается «этот сервис не смог» и цепочка идёт дальше. Если DNS завис — через 5 с это тоже «не смог». Если сам воркер упал (паника) — в логе одна строка, дальше обложек не будет до перезапуска, музыка не замечает.

Стрим: сервер ответил «подождите» (408/429) — ждём и пробуем снова, как при обрыве сети; ответил «уходите» (403/404 и прочие 3xx/4xx) — сессия заканчивается ошибкой, как сегодня. Запуск с битым адресом («без http://», «без хоста») — сразу сообщение и выход с кодом 2, без окна и без вечных переподключений.
