# Proposal

## Why

Аудит проекта (2026-11-04) показал асимметрию защиты двух HTTP-контуров: стрим-контур (`src/net.rs`) закрыт полно — таймауты всех фаз, `max_redirects(0)`, лимиты объёма метаданных, — а контур обложек (`src/cover.rs`) лишён сразу нескольких из этих защит и при этом единственный принимает URL из недоверенного JSON. Кроме того, классификация HTTP-статусов стрима убивает сессию на повторяемых отказах (408/429), синтаксически битый URL ретраится вечно вместо мгновенного отказа, а паника воркера обложек маскируется навсегда — обложки молча исчезают без единой записи в лог.

## What Changes

- **Контур обложек ужесточается до стандарта стрим-контура**: лимит размера тела ответа (сейчас `read_to_end` без ограничения — OOM-вектор), запрет редиректов и не-https URL (сейчас дефолт ureq: до 10 редиректов, возможен downgrade), allowlist CDN-хостов каждого сервиса цепочки (URL картинки приходит из недоверенного ответа поиска), `timeout_resolve` — зависший DNS больше не подвешивает единственного воркера.
- **Авария воркера обложек становится видимой**: паника воркера ловится и логируется один раз, дальнейшие запросы пропускаются — вместо молчаливого исчезновения обложек до конца жизни процесса.
- **408/429 при подключении к потоку — повторяемые статусы**: ретрай по лестнице backoff вместо перманентной смерти сессии («сервер отклонил запрос»). Остальные 3xx/4xx остаются перманентным отказом, как сегодня.
- **Битый URL запуска — ошибка старта**: URL без схемы http/https или без хоста отклоняется при разборе аргументов с кодом 2 до открытия окна (в обоих режимах) — вместо вечных переподключений каждые 10 с без выхода.

## Capabilities

### New Capabilities

(нет — все требования ложатся в существующие возможности)

### Modified Capabilities

- `album-art`: добавляются требования «Ограниченные сетевые обращения обложек» (лимит тела, без редиректов, только https, allowlist хостов, резолв-таймаут; нарушение трактуется как сбой сервиса в цепочке) и «Диагностика аварии воркера обложек» (паника воркера логируется, поиск отключается до перезапуска, воспроизведение не затрагивается).
- `audio-pipeline`: требование «Ошибки запуска» уточняется — HTTP 408/429 при подключении относятся к повторяемым сетевым отказам (ретраи с задержкой), а невалидный URL — не-сетевая фатальная ошибка запуска (headless: ненулевой код и stderr; UI-режим: диагностика до открытия окна).

## Impact

- **Код**: `src/cover.rs` (конфигурация агента, `get_bytes`, проверка хостов, воркер), `src/net.rs` (условие фатальности статусов в reader-цикле), `src/ui.rs` (валидация URL в `parse_args`).
- **Зависимости**: вероятна новая прямая зависимость `http` (разбор URI при старте; уже в дереве через ureq — решение фиксируется в design).
- **Тесты**: юнит-тесты `cover.rs` на fake-транспорте (перерасход тела, редирект, чужой хост, паника воркера), интеграционные на мок-сервере (429 → ретрай, 404 → фатал), таблица валидных/невалидных URL.
- **Вне скоупа**: контрольные суммы и SHA-пины CI (пункт 4 обзора), eviction дискового кеша обложек, восстановление (respawn) воркера после паники, рефакторинг стринговых исходов сессии.
