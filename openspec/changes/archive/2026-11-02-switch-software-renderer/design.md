# Design

## Context

`slint = "1.18"` сегодня берётся с дефолтными фичами:
`std, backend-default, renderer-femtovg, renderer-software, accessibility,
compat-1-2, system-tray` — оба рендерера вшиты, femtovg приоритетен.
Замеры живого процесса (Wayland, KDE 6.6, Intel Raptor Lake-P; femtovg —
окно в покое, software — покой/игра):

| Путь                | RSS      | PSS          | Доминанта                            |
|---------------------|----------|--------------|--------------------------------------|
| femtovg (текущий)   | 135 МБ   | 92.7 МБ      | libLLVM ~41 МБ + libgallium ~9 МБ (файловые), GL-anon ~49 МБ |
| renderer-software   | 52 МБ    | 32 МБ (покой) / 46 МБ (игра) | бинарник+шрифты ~19 МБ файловых; anon ~24 МБ, в т.ч. один блок ~16 МБ (источник не установлен — кандидат на отдельное расследование) |

Femtovg через glutin не поднимается на аппаратный EGL этой конфигурации и
работает через софт-стек Mesa (gallium/LLVM). Сцена окна статична
(render-on-demand Slint), GPU-конвейер избыточен.

Примечание к истории замеров: ранний замер «software = 3 МБ PSS» был
артефактом измерения (PID процесса `timeout`, а не sevfm) и исправлен;
корректные цифры — в таблице.

## Goals / Non-Goals

**Goals:**

- PSS запущенного плеера — единицы МБ вместо десятков (замер /proc, живой).
- Исключить femtovg/GL-стек из дерева зависимостей и бинарника.
- Сохранить текущий вид и поведение окна без изменений.

**Non-Goals:**

- Переход на другие рендереры (skia/wgpu/vello) — тяжелее femtovg.
- Оптимизация аудио-тракта и ICY — там памяти <1 МБ.
- Анимации сверх существующих: сцена остаётся прежней.

## Decisions

- **D1. Явный набор фич вместо дефолта.** `slint = { version = "1.18",
  default-features = false, features = ["std", "backend-winit",
  "renderer-software", "accessibility", "compat-1-2", "system-tray"] }`.
  Альтернатива — оставить дефолт и задавать `SLINT_BACKEND=software`
  (env в .desktop или set_var в коде): не убирает femtovg из бинарника
  и зависимости; отклонена. `backend-default` заменён на явный
  `backend-winit`: единственный нужный бэкенд на Linux и Windows.
  Осознанное следствие (ревью): env `SLINT_BACKEND=femtovg` у пользователя
  теперь даст ошибку выбора рендерера — femtovg не вшит; в репо и упаковке
  переменная нигде не задаётся, поэтому риск только ручной override.
- **D2. Совместимость фич сохранена.** accessibility, system-tray (ksni на
  Linux / нативный на Windows), compat-1-2 остаются — трей и доступность
  не должны меняться из-за смены рендерера.
- **D3. Критерий приёмки — замер, не только сборка.** После смены: живой
  запуск, PSS через smaps_rollup (ориентир: ≤ 50 МБ в покое и играющем
  состоянии — против 92.7 МБ у femtovg; GL-стек в /proc/…/maps отсутствует),
  вид окна — глазами (обложка, статусы, индикатор) плюс существующие
  ui-тесты. Источник оставшихся ~16 МБ anon (половина покоя) — вне этого
  change: кандидат на отдельное расследование.

## Risks / Trade-offs

- Software-рендерер медленнее на сложных сценах. Сцена простая (карточка,
  текст, индикатор, статичная обложка); фикс-кадр не анимируется
  непрерывно. Риск считаем принятым; при будущих тяжёлых анимациях —
  пересмотр (design-синк).
- Сглаживание/шрифты могут отличаться пиксельно от femtovg. Допустимо:
  вёрстка и элементы те же, попиксельного паритета с прошлой версией
  не требуется.
- Обновление Cargo.lock (выпадение femtovg-ветки) — ожидаемо, зона
  регрессии ограничена сборкой; полный локальный прогон гейтов обязателен.
