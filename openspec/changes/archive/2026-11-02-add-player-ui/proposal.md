# Proposal

## Why

Плеер существует только как CLI: единственное управление — сигнал процесса, а эфир (станция, трек, статус) печатается в stderr. Спека `radio-player` требует окно с кнопками «Играть»/«Стоп», отображением состояния и текущего трека; сетевой тракт и ICY-метаданные уже готовы (фазы 1 и ICY), их потребитель сознательно спроектирован заменяемым (`NowPlayingPrinter` в `main.rs`). Настал момент заменить CLI-представление окном.

## What Changes

- Окно Slint: название станции (`icy-name`), статус (Остановлено / Подключение / Воспроизведение / Буферизация / Переподключение), исполнитель и название трека при наличии, кнопки «Играть» и «Стоп».
- Повторные сессии воспроизведения в одном процессе: «Играть» запускает тракт, «Стоп» останавливает и возвращает в «Остановлено»; тракт можно запустить снова.
- UI-режим по умолчанию; новый флаг `--headless` сохраняет текущее CLI-поведение (запуск тракта сразу, вывод в stderr, коды выхода 0/2) — для терминала и существующих интеграционных тестов.
- Фатальные ошибки сессии (нет аудиоустройства, поток не MP3, отклонение сервером) в UI-режиме: сообщение в окне, возврат в «Остановлено», процесс продолжает работать; в headless — прежний код 2.
- Закрытие окна и SIGINT/SIGTERM в UI-режиме: полная остановка воспроизведения и сети, корректный выход с кодом 0.
- Заглушка под обложку в макете окна; сама цепочка подгрузки обложек (iTunes/Deezer/Яндекс + кеш) — отдельный будущий change, как зафиксировано в архиве фаз. Для того change: маппинг `TrackSlot → (artist, track-title)` на границе окна необратим — правилу видимости обложки «как у трека» потребуется третье свойство окна (флаг «это заглушка» или отдельный слот), из текущих строк его не вывести (находка ревью).
- Смена трека в представлении происходит по приходу метаблока из потока и опережает звучащий блок на заполненность буфера (≥ предбуфера). Синхронизация метаданных с воспроизводимым аудио (очередь метаблоков с привязкой к аудиосмещению в кольце, дренаж по позиции декодера) — осознанно вынесена в отдельный будущий change: самостоятельная тема с самым тяжёлым тестовым пластом.
- Обновление интеграционных тестов (`cli_mock`, `sigint_mock`, `sigint_live`) на запуск с `--headless`; новые тесты логики UI.

## Capabilities

### New Capabilities

- `player-ui`: окно плеера — управление воспроизведением (Играть/Стоп с доступностью по состоянию), отображение станции, статуса и трека, жизненный цикл приложения (закрытие окна, сигналы, фатальные ошибки сессии) и headless-режим запуска.

### Modified Capabilities

- `icy-metadata`: требование «Представление станции и текущего трека» — представлением по умолчанию становится окно UI; вывод в stderr остаётся только в headless-режиме.
- `audio-pipeline`: требование «Ошибки запуска» — завершение с кодом 2 и диагностикой в stderr scoped на headless-режим; в UI-режиме фатальная ошибка сессии показывается в окне без завершения процесса.

## Impact

- **Зависимости**: + `slint` (1.x, дефолтные фичи: backend-winit + renderer-femtovg) и `slint-build` для компиляции `.slint`-разметки через build-скрипт.
- **Код**: `main.rs` — разбор `--headless`, ветвление UI/headless, выделение одноразового `run()` в переиспользуемый запуск сессии; новый модуль UI (модель состояния, связка с окном) и файл разметки окна. Модули тракта (`buffer`, `net`, `pipeline`, `icy`) — без поведенческих изменений: их API (`PlaybackStatus`, `SharedNetStatus`, `SharedNowPlaying`, `spawn_reader`, `Mp3Source`) уже достаточен для сессий.
- **Тесты**: существующие тесты бинарника получают `--headless`; добавляются unit-тесты отображения статусов/эфира и интеграционный тест флага.
- **Лицензия**: Slint — GPL-3.0 / royalty-free / коммерческая; выбор зафиксирован проектом («Rust + Slint»), на распространение Apache-2.0 исходников это решение не влияет в рамках личного плеера.
