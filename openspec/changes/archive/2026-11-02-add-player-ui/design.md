# Design

## Context

Сейчас приложение — CLI: одноразовый `run()` в `main.rs` создаёт все структуры тракта (буфер, `GarbageBudget`, `Link`, слоты статусов/эфира/исхода), поднимает reader-поток, открывает аудио-устройство после предбуфера и живёт до конца потока или сигнала. Остановку по сигналу делает сторож-поток прямым `process::exit(0)`; обработчик `ctrlc` ставится один раз на процесс (ограничение крейта). Потребитель эфира — `NowPlayingPrinter` (poll со дедупликацией), спроектированный на замену UI без изменений тракта. Модули lib (`buffer`, `net`, `pipeline`, `icy`) предоставляют всё нужное UI: `PlaybackStatus` + `playback_status()`, `SharedNetStatus`, `SharedNowPlaying` (`station`, `TrackInfo { artist, title }`), `spawn_reader`, `Mp3Source`, `RingBuffer::phase1`. Интеграционные тесты запускают бинарник с позиционным URL. Slint в проекте ещё отсутствует; актуальная стабильная — 1.18.1.

Ключевой факт: тракт одноразовый по построению (закрытый буфер, завершённый декодер, слоты исхода), но все его структуры — просто значения, создаваемые заново на запуск. Перезапуск сессий — это слой над трактом, сам тракт не меняется.

## Goals / Non-Goals

**Goals:**

- Повторные сессии «Играть/Стоп» в одном процессе без поведенческих изменений модулей тракта.
- UI-логика (маппинг состояний, дедупликация эфира, гейты кнопок) — обычные функции lib, тестируемые `cargo test` без окна и без Slint.
- Headless-режим сохраняет текущее поведение точно; существующие тесты продолжают работать с добавленным `--headless`.

**Non-Goals:**

- Обложки (цепочка iTunes/Deezer/Яндекс, кеш) — отдельный change; в окне только статичная заглушка.
- Трей, громкость, выбор станции из UI, локализация, кастомные шрифты.
- Автоматизация отрисовки окна в CI (публичного стабильного testing-API у Slint нет; `i-slint-backend-testing` без semver — отклонён).
- Отключение/сужение дефолтных фич Slint (accessibility, system-tray) — осознанно берём дефолт.

## Decisions

### D1: Сессия как слой в lib, тракт — чёрный ящик

Новый модуль `src/session.rs`: `PlayerSession::start(url, process_stop) -> io::Result<SessionHandle>`. Каждая сессия создаёт свежий набор структур (как сейчас `run()`: буфер 512 КиБ, бюджет мусора, `Link`, слоты) и worker-поток с перенесённым из `main.rs` циклом (предбуфер → устройство → `Player` → ожидание). Отличие от CLI-цикла: цикл воркера дополнительно проверяет флаг остановки сессии и выходит сам (в CLI выход делал сторож процесса через `exit`), после чего `player.stop()` + drop устройства. Аудио-устройство открывается и закрывается внутри сессии — повторные сессии не делят устройство.

Результат воркера — `SessionOutcome::{Stopped, Fatal(String)}`: существующая классификация исходов (`link.fatal`, `reader_panicked`, гибель потока вывода, `Outcome::DecoderError` → `Fatal` с сообщением; сигнал/штатный конец → `Stopped`). Код выхода 2 — остаётся концерном headless-обвязки.

Альтернатива — переиспользование структур тракта между сессиями — отклонена: требует донастройки закрытия/сброса в нетронутых модулях ради экономии 512 КиБ и одного потока.

### D2: UI-состояние и маппинг — чистые функции в lib

Модуль `src/ui.rs` (без Slint): `UiState { Stopped, Connecting, Playing, Buffering, Reconnecting }` с `label()` («Остановлено» + метки `PlaybackStatus`), маппинг `(session_alive, NetStatus, playback_started, underrun) -> UiState` — чистая функция поверх существующей `playback_status()`. `PlaybackStatus` не расширяется: «Остановлено» — не состояние живого тракта. Ошибка сессии — отдельная строка (`error` в модели представления), статус при ошибке — «Остановлено» (спека).

`PlayerView` — модель со дедупликацией по переходам (эволюция `NowPlayingPrinter`): poll сравнивает с предыдущим состоянием и отдаёт только изменения. Трек-строка — слот `TrackSlot { Track, Title, Placeholder }` (уточнение ручного чек-листа 4.3: трек и будущая обложка видны только при живой сессии): трек — исполнитель и название; сырой `StreamTitle` без JSON — только название; рекламная вставка, до первого метаблока и «Остановлено» — заглушка с названием станции. Для различения вставки и трека `icy::TrackInfo` стал enum'ом `Track { artist, title } | Insert { title } | Raw { title }` (`Raw` — StreamTitle без JSON: это трек в свободном формате, не реклама); headless-печать вставок названиями не меняется. Unit-тестируется таблицей переходов.

### D3: Связка с окном — опрос таймером из главного потока

Воркер сессии пишет только в разделяемые слоты (reader уже так делает); главное слово за poll-таймером Slint (`TimerMode::Repeated`, 100 мс — тот же ритм, что `POLL_INTERVAL`): читает слоты + факт живости воркера, обновляет `PlayerView`, пишет свойства окна. Таймер создаётся в main-потоке (ограничение Timer — поток, не факт запуска цикла) и хранится в структуре связки (drop таймера глушит его).

Альтернатива — `invoke_from_event_loop` из тракта — отклонена: потребовала бы callback-каналов в lib и связи тракт→UI; опрос — уже архитектура проекта (`NowPlayingPrinter::poll`), и тракт не узнаёт про UI.

### D4: Окно — `.slint`-файл, Slint только в bin

Разметка `ui/player-window.slint` + `build.rs` со `slint_build::compile` (slint-build 1.18), подключение — `slint::include_modules!()` в `main.rs`. Свойства: `station`, `status`, `artist`, `title`, `error` (строки), `can-play`, `can-stop` (bool); callbacks `play()`, `stop()`. Макет: заголовок окна, станция, статус, исполнитель/название, квадрат-заглушка под обложку, две кнопки внизу. Сланг-слой (callback→сессия, таймер→свойства) живёт в `main.rs`; lib не зависит от Slint — быстрые unit-тесты и чистая слоистость.

Альтернатива — inline-макрос `slint!` без build.rs — отклонена: файл разметки лучше масштабируется на фазу обложек (изображения, стили) и держит build-скрипт тривиальным.

### D5: Сигналы и завершение в UI-режиме

Обработчик `ctrlc` ставится один раз в `main` до ветвления режимов (крейт допускает один хендлер на процесс); его действие выбирается по зафиксированному режиму: headless — существующий сторож `process::exit(0)`; UI — `slint::quit_event_loop()` (документировано: вызов из любого потока; `Result`-ошибка «цикл уже завершён» глотается) и установка флага остановки активной сессии. После возврата `run_event_loop` (закрытие окна или сигнал): остановка сессии, join воркера с таймаутом; гарантия «код 0 ≤ 1 с» — за сторожем-страховкой (`exit(0)` при превышении), как в headless.

### D6: Аргументы — разбор вручную, без clap

`--headless` в любой позиции + первый позиционный аргумент = URL (по умолчанию станция). Один флаг не оправдывает зависимость. Неизвестный флаг или `--headless`-конфликт — диагностика в stderr и код 2 до открытия окна (консистентно с CLI-конвенцией проекта; предположение — спекой не оговорено).

### D7: Зависимости

`slint = "1.18"` (дефолтные фичи; на Linux это backend-winit + femtovg, software-рендерер остаётся запасным), `[build-dependencies] slint-build = "1.18"`. Кириллица — системные шрифты через fontdb (ограничение «western scripts» касается только software-рендерера, дефолтный путь им не является).

### D8: Тесты

- Unit (lib, без Slint): маппинг `UiState` (таблица всех комбинаций входов), дедупликация `PlayerView`, разбор аргументов, классификация `SessionOutcome`.
- Интеграционные: существующие `cli_mock`, `sigint_mock`, `sigint_live` получают `--headless` в командной строке запуска (поведение и ожидания не меняются); новый тест — `--headless` с URL покрывается существующими сценариями.
- Окно в CI не запускается; ручная проверка по чек-листу (tasks).

## Risks / Trade-offs

- [Окно не тестируется автоматически] → вся логика окна (маппинг, дедуп, гейты кнопок) вынесена в тестируемые функции lib; чек-лист ручной проверки в tasks.
- [Timer до `run_event_loop` прямо доками не разрешён] → ограничение сформулировано про поток; таймер создаётся в main-потоке; запасной вариант при проблеме — запуск таймера через `invoke_from_event_loop` после старта цикла (замена одной строки в связке).
- [Гонка за аудиоустройство при быстром «Стоп»→«Играть»] → «Остановлено» (и доступность «Играть») ставится по факту завершения воркера, а не по нажатию «Стоп»: teardown длится ~100–300 мс, следующая сессия стартует только на мёртвом воркере. Компромисс: кнопка «Играть» недоступна эти доли секунды — безопаснее разделения устройства.
- [Задержка остановки звука по «Стоп»] → воркер проверяет флаг каждые 100 мс, затем `player.stop()` + drop устройства — вписывается в секундную норму спеки с запасом ~10×.
- [Femtovg/шрифты на экзотических системах] → в дефолтных фичах остаётся software-рендерер (переключение через `SLINT_BACKEND`); целевая платформа — Linux-десктоп с системными шрифтами.

## Migration Plan

Десктоп-приложение без внешних потребителей: последовательная реализация по tasks в одном change, `--headless` вводится вместе с UI, тесты обновляются в том же change. Откат — `git revert` change-коммита; самостоятельной миграции не требуется.

## Open Questions

- Финальный вид окна (стиль, размеры, тема) — доводится при реализации вручную; на спеки и разбиение задач не влияет.
