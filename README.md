# sevfm (sevfm-rs)

[![CI](https://github.com/kolokolovg/sevfm-rs/actions/workflows/ci.yml/badge.svg)](https://github.com/kolokolovg/sevfm-rs/actions/workflows/ci.yml)

Настольный плеер онлайн-радио **«Говорит Севастополь»** на Rust + Slint.

Цель: нативный бинарник с малым потреблением ОЗУ и процессора
(целевой ориентир — десятки МБ RSS).

## Стек

- **Rust** (edition 2024)
- **Slint** — UI (render-on-demand) + свёртывание в трей через `tray-icon`
- Аудио-тракт (фаза 1): `ureq` (HTTP/TLS) → `symphonia` (MP3-декодер) →
  `rodio`/`cpal` (вывод)

## Статус

Фаза 1 — тракт живого MP3-стрима (буфер, устойчивость к мусору,
остановка по сигналу); фаза ICY — метаданные эфира: название станции и
текущий трек из ICY-метаблоков. Спецификации поведения:
[`radio-player`](openspec/specs/radio-player/spec.md),
[`audio-pipeline`](openspec/specs/audio-pipeline/spec.md),
[`icy-metadata`](openspec/changes/add-icy-metadata/specs/icy-metadata/spec.md).

## Сборка

Linux — сначала системные библиотеки (ALSA — вывод звука через
rodio/cpal; xkbcommon и fontconfig — окно Slint/winit):

```bash
sudo apt install libasound2-dev libxkbcommon-dev libxkbcommon-x11-dev libfontconfig1-dev
cargo build --release
```

Windows — `cargo build --release`; иконка exe вшивается ресурсом из
`packaging/sevfm.ico` (winresource в build-скрипте).

### Пакеты

deb — бинарник + `.desktop` и иконка hicolor (приложение «SevFM»
появляется в меню с гербом):

```bash
cargo install cargo-deb
cargo deb          # → target/debian/sevfm_<версия>_amd64.deb
```

Релизный deb собирается CI на Ubuntu 24.04 — требуется glibc ≥ 2.39
(Debian 13+/Ubuntu 24.04+; на более старых — собирайте локально).

### CI и релизы

- Каждый пуш/PR — [CI](.github/workflows/ci.yml): форматирование, clippy,
  офлайн-тесты (ubuntu) + release-сборка exe (windows).
- Пуш тега `v*` — [Release](.github/workflows/release.yml): `sevfm.exe`
  в zip и deb прикрепляются к GitHub Release. Имена файлов — из версии
  `Cargo.toml`: расхождение с тегом останавливает публикацию. Ручная
  тестовая сборка — Run workflow в Actions (без публикации; с галочкой
  `publish` и запуском на теге — публикует).

## Запуск (фаза 1)

```bash
cargo run --release                    # станция по умолчанию (sevfm.ru)
cargo run --release -- <URL-стрима>    # произвольный живой MP3-поток
```

Тракт: сетевое чтение в выделенном потоке → кольцевой буфер (512 КиБ,
предбуфер 64 КиБ) → покадровый MP3-декод → вывод PCM. Воспроизведение
идёт из буфера: при обрыве сети звук не прерывается, пока есть данные;
долгий обрыв — пауза с автоматическим возобновлением; соединение
восстанавливается с нарастающей задержкой (1 → 2 → 5 → 10 с).

Статусы в stderr (по состояниям спеки): `Подключение`, `Воспроизведение`,
`Переподключение`, `Буферизация`. Ошибки кадров логируются не чаще раза
в секунду.

Метаданные ICY: при подключении запрашиваются метаданные
(`Icy-MetaData: 1`); при наличии `icy-metaint` блоки метаданных
вырезаются из потока до декодера — звук идёт без искажений, а в stderr
появляются `станция: …` (из `icy-name`) и `сейчас в эфире: ИСПОЛНИТЕЛЬ —
НАЗВАНИЕ` при каждой смене трека. Смена трека публикуется синхронно со
звуком — когда звучит аудио, к которому относится метаблок, а не в момент
его приёма (станция — сразу); во время буферизации заголовок замирает.
Рекламные/новостные вставки показываются
названием без исполнителя. Сервер без ICY — легитимный режим: чистый MP3
без строк эфира.

Остановка — Ctrl+C (SIGINT) или SIGTERM: процесс завершается кодом 0
в течение секунды, без деструкторов (ресурсы освобождает ОС).

Коды выхода: `0` — сигнал или штатный конец; `2` — фатальные ошибки
старта (нет аудиоустройства, поток не распознан как MP3) и сбои живого
цикла (ошибка декодера, аварийное завершение потока чтения); сетевые
ошибки, мусорные лимиты и «капающий» сервер (скорость ниже 2 КиБ/с) —
переподключения с логом (мусор лечится переподключением, не завершением),
выход только по сигналу.

Живые тесты (требуют сеть; SIGINT-тест — ещё и аудиоустройство):

```bash
cargo test live_stream_reads_first_64k -- --ignored --nocapture
cargo test --test sigint_live -- --ignored
```

Прочие тесты сети не требуют: сценарии обрыва, мусора, молчания и не-MP3
ответов обслуживает локальный мок-сервер (`tests/common/mod.rs`,
`TcpListener` со скриптуемыми сценариями соединений).

Заметка о cargo-прокси: если `static.crates.io` недоступен напрямую
(TLS до Fastly дропается провайдером), пропишите прокси локально
в `~/.cargo/config.toml` — в репозиторий конфиг не коммитится:

```toml
[http]
proxy = "http://127.0.0.1:10809"
```
